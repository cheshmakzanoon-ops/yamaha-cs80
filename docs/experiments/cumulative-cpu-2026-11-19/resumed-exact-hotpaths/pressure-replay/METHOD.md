# Real VST3 two-level pressure check
This Linux x86-64 driver uses the repository's frozen factory-eight SDK scaffold. It opens real 32-bit audio VST3s, enables the SUB pressure-rate and cutoff modulation controls, and delivers note and polyphonic-pressure events across six fixed histories. All cases use Standard at 48 kHz / 64 frames, 32 warm-up blocks, a five-block comparison window and one continuation. Note and pressure events have been consumed **before** the measured window. Four simultaneous keys receive the same pressure in `chord4`; the other cases sound the same eight notes/velocities and differ only in the pressure words. All five eight-key audio streams differ from one another in the baseline, so an ignored pressure fixture cannot explain the equivalence.

- `split8`: four keys at 0.81, four at 0.34;
- `one8`: one trailing key at 0.71, seven at zero;
- `irregular8`: two noncontiguous groups with the first pair equal;
- `distinct8`: eight different pressures, unspecialized;
- `uniform8`: the already-shipped fully uniform specialization.

On each build, each history has one untimed native capture and four Valgrind 3.24.0 Callgrind captures. The first four real plug-in callback entries are repeated, and a separate fifth entry must exactly add up to the five-entry capture. Compare PCM, four public component state blobs, callback/FP/status/event-count/error observations and one continuation across builds *within* each runtime. The collector permits the native and simulated sticky FP traces to differ between runtimes; their PCM and public states must agree even across runtimes. The counter is the real plugin process entry edge only, after verifying that the wrapper accounts for all by itself plus this single edge. These are executed guest instructions, reads and writes, never native wall or CPU time, DAW CPU or target-device certification.

Reproduce with `bash run.sh PROJECT VST3_SDK BASELINE.so CANDIDATE.so NEW_OUT`; `VALGRIND`, `VALGRIND_INCLUDE_ROOT`, `CXX`, and `JOBS` are optional. The VST3 SDK path used here is the one contained in the matched JUCE revision. Python 3.11+ is needed. Compare only matched builds and toolchains. The executable paths and build fingerprints from the original receipts are not expectations for unrelated machines.

`direct-pressure.cpp` is a separate strict GCC/x86-64 component/fault probe. To repeat on each of the original and candidate source roots (not combined sources), compile it with `g++ -std=c++20 -O3 -DNDEBUG -fPIC -ffunction-sections -fdata-sections -I"ROOT/src/core" -I"ROOT/src" direct-pressure.cpp -Wl,--gc-sections -o probe`; run each executable with stdout to a new binary file and require byte equality. It compiles the actual Engine translation unit to reach its private, TU-local bus helper, without modifying production accessibility. It checks potential exceptions in a standalone process on Linux with a signal handler, not inside a DAW. The 170,752 result records per build contain every binary result, MXCSR, x87 control/status, errno and trap info. Compare within the same compiler: different GCC releases may make different old-path observations. The public plug-in remains uninstrumented.
