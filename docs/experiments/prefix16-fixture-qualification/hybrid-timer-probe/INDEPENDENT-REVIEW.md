# Independent timer-fixture review

Read-only review of proposed-timer-fixture.patch, TimerTestWait.h, unchanged PumpUntil.h, test call sites and local JUCE timer implementation. No production or proposal edits. Recorded three repeats each pass, notification1163checks and studio27checks; helper smoke12checks passes. Repetition alone is not the basis of the review.

No new correctness blocker found. Exact notification/dirty counts, thread and change flags, parameter-notification isolation, reentrant saved-state equality, first-delivery count1, separate next-delivery count1, and subsequent zero-delivery checks remain. Positive waits stop on ANY notification rather than waiting for exactly the desired count, so an excess count does not get silently accepted. Changed-action cases retain a quiet-period negative check after reset. Coalescing and reentrant sections still inspect original exact predicates. Studio restore is observed through the real8Hz timer; no direct sync replacement is introduced.

The130ms barrier has a source-backed ordering argument for these tests: StudioMount starts8Hz(125ms); UndoableParameterState inherits APVTS10Hz(100ms) and overrides callback without invoking base adaptive timer rescheduling. The barrier is registered after these existing timers. JUCE subtracts elapsed time from all countdowns, maintains a sorted queue and dispatches due timers before later countdowns. Thus observing barrier delivery witnesses progress beyond at least one existing timer opportunity, rather than assuming a sleep updated countdowns. This is contingent on the tested timer periods and must be revisited if production changes them. A future smoke test with explicit100/125ms counters would make that dependency more visible, but source inspection currently supports it.

Limits/wording: PumpUntil is an existing polling timeout, not a hard2second execution deadline. It checks readiness before timeout and may accept readiness after a long final pump. Assertions labeled 'before deadline' should not be cited as strict wall-clock latency or real-time qualification. Completion at deadline is intentionally accepted in PumpUntilTests. JUCE callTimers may dispatch multiple timer cycles if callbacks/pumping are very slow; exact reentrant checks will expose that as a failure rather than hide it. This proposal improves synchronization but does not prove universal scheduling robustness or individual-callback timing.

No numeric audio thresholds or production callback behavior changes. The test intentionally replaces an unreliable fixed sleep with bounded event readiness, not a production latency contract.
