# Independent dynamic-admission cost review

Read-only code/data audit, no compilation or new timing. Independently parsed all raw CSVs, rejected duplicate keys, required exact key sets, checksum strings and zero nonfinite counts. Verified current thread-CPU executable hashes against both active and idle input-hashes receipts. Three completed active pairs each have 36 rows; wide pass 100 rows; baseline/idle runs 19 rows each. Completion markers for all six long idle runs are zero.

Source Performance warmed-held median case CPU ratios reproduce 0.98646915, 0.97640855, 0.98743908: modest 1.26–2.36% relative improvement in this selected 48k/128-frame, quick, 256-callback Linux fixture. Original quick wall ratios and wide wall median also improve. Ratios are medians of case ratios, NOT ratios of median CPU RTFs. CPU RTF is callback thread CPU / rendered duration, not whole-system CPU percent. Measurement wraps control-frame/event application and render plus two wall-clock reads; excludes synthesis/verification/stat aggregation. Both binaries receive identical added clock overhead.

Not every case improves. Source Performance mpe_chorus_reverb selector10 release_tail is slower in all three active CPU pairs: 1.026892, 1.012190, 1.003182. Other case regressions vary, including larger individual outliers. Therefore no blanket regression-free claim.

Original quiet-isolation wall ratio 1.145165 did not reproduce at that magnitude in longer idle CPU checks: 1.013073, 0.988296, 1.051697. Third idle round also has large unrelated regressions including scalar legacy and isolation release paths (maximum ratio 2.854274). Engine selects scalar processInternalSampleImpl for zero active voices, so changed batch kernel is not executed by truly quiet idle; direct per-sample added kernel cost cannot explain that idle result. This supports environmental/code-layout uncertainty, not proof that all variation is harmless. Thread CPU excludes descheduling but not frequency/cache/host-resource effects.

Verdict: evidence supports a narrowly qualified modest active-workload benefit, with exact recorded numerical checksums. No identified structural idle kernel penalty; timings do not establish absence of all regressions or universal benefit. Publishing as this bounded optimization is defensible if existing correctness qualification is retained and the small release-case regressions/noise are disclosed. It does not establish the user's under-2% target, DAW realtime qualification, or another CPU/platform's cost. Do not discard the initial wide/idle outliers. No cherry-pick or publication performed by reviewer.
