# Independent read-only rerun path audit

Scope: selected557-test inventory in nonwindow-inventory.json, actual registered commands, compiled-source mappings from compile_commands.json, and directly referenced Python/shell/CMake wrappers. No active output directory was moved, deleted or modified; no tests were run and no source was edited for this audit. Audit artifacts alone were added here.

## Findings

1. Confirmed the two direct fixed-path fresh-only admissions: LfoRandomSwitchingTests.cpp and LfoRandomVariableRateTests.cpp require `!exists(out)` and receive fixed build-directory paths from registration. Those are the already-observed124/125 failures. Other source files with similar fresh-only guards are built generators/probes without selected direct registrations; no selected wrapper was found routing into those guards with a persistent fixed output path.

2. All51 referenced script entries (48unique scripts) classified:43 references have unique TemporaryDirectory/mktemp roots,3 are read-only numeric oracles using child stdin/stdout,4 are fixed missing/truncated fixture-input rejection wrappers,1 is the pluginval shell under its outer mktemp test harness. Full commands, source hashes and relevant lines are in wrapper-path-audit.json. Batch-admission's optional --output path would require freshness, but actual registered command omits it and takes TemporaryDirectory. CLI capture/render/benchmark negative and positive cases generate outputs beneath fresh temp roots. Deliberately occupied paths inside those roots are negative controls, not stale suite state. CMake fixture wrappers create no outputs; an unexpected source file at the reserved `missing` input name could affect their expected rejection but the suite does not create that path.

3. Distinct evidence-lifetime risk, not a fresh-only admission failure:276 registered VST3 witness commands from44 source families accept276 distinct fixed output directories with create_directories(argv[4]) and truncate/rewrite named captures. dsp-probe similarly creates/reuses its fixed directory. These normally tolerate reruns, and witness comparisons use newly rendered in-memory results, rather than treating old captures as a successful result. However extra files or files from an interrupted prior execution may remain. Do not treat a whole directory tree as exclusively from the latest run without a run-specific manifest/hash audit. Details in fixed-overwrite-capture-paths.json. No same-directory collision among those276 selected registrations was found.

4. Other detected file-writing functions are not entered by their selected modes: oscillator test uses no-benchmark, not render output; LibraryAudit has no --calibrate; FilterBatchEngine lacks --write-corpus; memory qualification registration uses check mode (only existing build directory creation). JUCE processor fixture tests use TemporaryFile roots. Selected wrapper scripts exercise filesystem behavior in temporary roots. Display-dependent output modes excluded from this557 inventory are outside this audit.

## Conclusion and limits

No additional fixed-existing-directory admission blocker was identified beyond the two LFO tests. This is a source/registration audit, not proof against all external filesystem interference or future source changes. Existing capture overwrite behavior can destroy previous evidence or retain unrelated stale extras; archive/manifest decisions belong before/after runs, never by moving active paths mid-run. Environmental cache/settings failures (for example Fontconfig or timer scheduling) are separate from the fresh-directory issue and are not ruled out here.
