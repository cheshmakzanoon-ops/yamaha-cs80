# MCM entering/leaving-channel cancellation

## Bounded specification-backed correction

[MPE v1.1](https://midi.org/mpe-midi-polyphonic-expression) §2.2.3 (page 13) says that changing Zone configurations must stop Sounding Notes and reset controls on channels entering or leaving MPE control. This change repairs the unambiguous membership transition subset: a channel changes between `none` and any member/manager role after an accepted MCM. It is not full §2.2.3 conformance. Appendix F's broader note-stop summary and still-MPE zone/role reassignment remain separate work.

On `9db55f71`, a standalone core witness reproduced surviving notes across both entering and leaving transitions in Legacy and Circuit: eight checks, four failures, while the unchanged-channel controls passed.

## Implementation boundaries

A single affected-channel mask clears scanner events, unassigned waiting keys and ARP source obligations before stopping affected held, released and pedal-held voices. It recomputes bookkeeping once and only then reconsiders unaffected waiters. It does not sequentially panic each channel, which could promote another affected key between operations. Existing channel-zero panic and CC120/CC123 behavior remain unchanged.

Affected channel-owned pedal state, raw member expression and RPN selectors reset. Clearing a disabled manager's selector means a later bare Data Entry MSB cannot reactivate that zone; a sender must select RPN 6 again. Negotiated range values retain their existing MCM behavior. The native processor mirrors the actual accepted membership change into host/UI held masks and CC88 velocity-prefix state. Pressure-gesture attribution is conservatively invalidated globally, matching the existing panic-style policy; that attribution is not claimed to survive on unrelated channels. Ignored NRPN/member RPN 6 traffic does not clear observers. MIDI learn already rejects protocol CC6 assignments, so accepted MCM data remains protocol input.

Shared modulation, expression, ribbon, pressure and scaled manager buses are not channel-owned in the current model and are not reset here. Resetting them via CC121 would modify unrelated channels and still would not be a full reset. Same-layout MCM and role/zone transfers where every channel remains under MPE control receive no new cancellation from this mask. Existing captured manager-zone routing is not rewritten. Shared effects/noise histories may continue after note cancellation; this is not a zero-output panic guarantee.

## Qualification

The initial actual-processor fixture reproduced 884 failures in 4,508 checks, with every unaffected/positive control passing. The fixed initial fixture passed 4,508/4,508. It covers Legacy/Circuit, eight/sixteen voices, both zones, membership expansion/shrink and enable/disable, held/released/pedal voices, host masks, CC88 ordering, selectors, scanner/waiting/ARP keys and retained unrelated obligations. The final expanded fixture passed 5,896/5,896, including same-zone manager/member and conventional-gap preservation, real UI gesture release/replacement safety and rejected protocol-CC6 learning. The affected native build completed 44 steps followed by two fixture steps; corrected fixture rebuilds completed six then two steps. Two existing snapshot enum-conditional warnings remain. The final selected integration run passed 27/27 in 107.20 seconds, including all six native VST3 rate/mode configurations, related core/native MPE, conventional bend, tuning, controller, allocation, handoff, mirror and undo cases. Independent source/test review approved this bounded feature, and the same 27-test selection independently passed 27/27 in 109.06 seconds. The repeat recorded membership 5,896/0, member retarget 284/0, manager routing 1,164/0, tuning 39,285/0, released targets 7,464/0 and allocation 204/0. No complete MPE, external controller/DAW, CPU/deadline or universal offline-render qualification is claimed.

Earlier member-range, released-target, manager-routing and tuning-expression tests intentionally expected historical voices to survive a membership crossing. Their crossing assertions now require termination and fresh defaults. The release-routing test retains its separate still-MPE role-change witness by using a direct MCM instead of a layout helper that temporarily disabled both zones. This is an intentional behavior change, not a compatibility-only optimization.

The first expanded integration run passed 24/27 in 109.87 seconds. Two historical routing suites still asserted surviving membership-crossing notes and were updated to require termination while retaining fresh-note routing and direct still-MPE transfer coverage. The new fixture also had 36 erroneous learned-CC6 expectations: MIDI learn intentionally rejects protocol CC6, so those controls were corrected to assert rejection and normal MCM processing. No production code or tolerances changed in response to those fixture corrections.

The second integration run passed 26/27 in 109.46 seconds, with the expanded membership fixture at 5,896/0. Four remaining pitch-witness failures inspected fixed slot zero after cancellation instead of the newly allocated voice. The witness now resolves the fresh note’s actual slot before checking its unchanged routing; production and tolerance values remain unchanged.
