## Reviewed persistence and playback paths

| Path | Source behavior and existing regression coverage |
| --- | --- |
| Older session | `normaliseRestoredState()` completes a detached tree for every `P_numParams` entry using its declared default. Missing Material values therefore replace stale receiving values with zero; finite values are clamped and discrete choices snapped. Earlier duplicate children are removed using the same final-child authority as JUCE. |
| User preset | `loadUserPreset()` calls that same normalizer before replacing APVTS state. Its three intentional session-setting overrides do not include Material. Tests cover material-free `.5` user files over a receiving instance with nonzero materials and verify the defaults reach the audio thread. |
| Inactive A/B slot | `readLibraryState()` iterates the complete parameter range and uses each declared default rather than the active slot's live value. Tests remove the two Material properties from an inactive `.5` slot while preserving its twelve prior body controls. |
| Session / file round trip | The host fixture uses distinct fourteen-control vectors, including nonzero Material values, and checks replacement of different live settings through both APIs. Incompatible saved combinations remain saved data; the signal generator's compatibility rule determines their neutral sound. |
| Undo / redo | All fourteen controls receive separate balanced parameter gestures, with checks that undo/redo restores the physical value and preserves the other controls. |
| Host automation | Explicit new-choice tests require ten named options, host indexes 308/309, AU hint 19 and all ten normalized values. Frozen previous 202-core/308-host hashes and definition hashes prevent reinterpretation of old automation. |
| Factory / MIDI recall | Existing tests compare current factory/MIDI recall with complete parameter vectors and fresh-note rendering, including body-off/return transitions. Program addresses stay intact. |
| Held notes | Engine rank settings carry Material into `InstrumentBody::noteOn()` at acceptance. The host fixture tests all nine materials on both ranks: a live selection must leave held-note samples bit-identical and must audibly change the next accepted note. |

## Remaining qualification scope

Actual processor save/load, native host automation, AU ordering, GUI integration and the held-note host fixtures remain gates of the committed native builds. They were inspected here but **not executed by A34**. Loading an old session retains its stored voicing; obtaining revised factory recipe values requires explicit factory LOAD / RELOAD and fresh notes. Compatibility does not mean that a newer material sound can be reproduced by an older plugin.

No production code, tests, preset identities, thresholds, commits or remote state were changed.
