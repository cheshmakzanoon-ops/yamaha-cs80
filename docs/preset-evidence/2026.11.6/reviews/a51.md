# A51 — five-lane macOS archive/validator binding

Created a separate `.6` successor to the historical A37 helper. It requires all five macOS validator consoles, including `pluginval-au-seed-c76-regression.log`; checks exactly one matching validation input path in each; and checks exactly one correct fixed-seed record for both AU GUI regressions (`0x2b4eef5`, `0x3c99748`). The complete archive, API digest/size, source/revision/run, architecture, AU executable and immutable-snapshot checks are retained. Existing `.5` helpers were not edited.

The new report exposes each fixed seed and changes the remaining outcome gate to **all-five-validator-lanes**. It does not turn a matching path or seed into a successful validator result. `release_qualified`, `validated_bundle_identity_established` and `run_attempt_bound` remain false. Original authenticated job/step exits, upload/attempt binding, whole installed-AU directory comparisons, strictness/program/failure counts, source-to-packager ordering and actual native tests still require their independent evidence. Across all systems the current workflow requires fifteen validator lanes.

## Executed verification

**22 synthetic test methods pass, zero failures.** The original inert-fixture contracts are retained, with additional rejection of missing new-seed console, wrong new-seed input, repeated new-seed invocation, and missing/wrong/repeated seed records in either fixed-seed lane: **nine additional negative mutations**. Fixtures deliberately contain no validator `SUCCESS`, demonstrating that helper success cannot be reported as native release success. Both native architecture headers and the actual committed `fcc3c8e` source loader are exercised.
