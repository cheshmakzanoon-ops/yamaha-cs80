The frozen `.4` native evidence parser hard-codes thirteen validator lanes. JSON can remap its exact members but cannot add the new Mac regressions. A separate `.6` [parser](../verification/a52/parse-native-evidence.py) therefore adds the required `au-gui-seed-c76` lane on both Mac targets: fixed seed `0x3c99748`, GUI coverage, the new console/report names and the exact workflow-step name. Its roster is **three Linux, two Windows and five per Mac: fifteen lanes**. Each console/report must also contain exactly one validation-start marker. Existing strictness-10, 523-program, clean terminal-success, GUI, fixed-seed, Linux original-child and retry observations remain.

A separate [archive binder](../verification/a52/bind-parser-archives.py) pins the new parser's SHA-256 **`f192bf2ff70d4501f73875eb5bb6416b9adc3b77912e165da4305302724cd846`** and 18,241-byte length, checks that identity in the observation, and verifies the unchanged historical parser against the requested Git source. It binds each parsed archive and member to the actual immutable ZIP snapshot and its supplied API object. This closes the previous gap in which parser summaries were not bound to the archive bytes actually inspected. Missing JUCE provenance is rejected by the binder.

The new analysis parser is not part of the compiled source. Its local reviewed identity is pinned separately; its historical predecessor is authenticated to the requested source tree. No historical helper was modified.
