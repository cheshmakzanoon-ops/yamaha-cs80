# Modern preset role audit — assignment 37

The final `2026.11.1` inventory contains **24 modern-tagged programs**. Exactly
those 24 programs have an active authored modern LFO, FX slot or arpeggiator.
No tag/activation mismatch was found. All **46 static inventory and derived-law
checks pass**. No production file was changed and no new audio was rendered.

## Mode behavior

`Engine::renderPolicy` gives Pure/isolation precedence over the Circuit flag.
Ordinary Circuit (`source_performance=1`, `parity_mode=0`) uses source models
while retaining the modern LFO, FX and arpeggiator overlays. `buildSettings`
copies their factory controls into the effective settings; only Pure masks
them. The destination accumulators feed rank pitch, filter cutoff, level CV,
pan and pulse width, and the serial FX chain follows the original chorus.

Pure sets LFO depth and destination to zero, FX type/model/mix to zero, and
arpeggiator enable to false. Its raw stored controls remain intact. Factory
recall preserves the current session Pure flag, so selecting a modern preset
does not silently turn Pure off. Ordinary input notes still play the dry voice
when the arpeggiator is suppressed.

`PluginEditor::showAdvanced` changes Studio overlay visibility, focus and
painting. It does not change the engine policy or enable modern DSP. A player
can close Studio and continue hearing the authored modern feature.

FX model zero explicitly selects the classic type. It is not bypass when the
classic type is nonzero and mix exceeds .001. This distinction matters for the
two phaser programs. Model 1 selects the three-tap ensemble; the default classic
chorus is a separate path.

The five echo descriptions match `0.06 * 20^A` seconds within 0.5 ms after
float32 authoring. These are nominal targets: tape wow/flutter and feedback
remain active. Arpeggiator rates feed an interval of `1/rate`; gate time is 58%
of that interval, or 45% for random mode. Arp Bass therefore completes a
1.5 Hz filter cycle over four 6 Hz notes, and Random Arp changes brightness at
half its note rate, matching their descriptions.

## Evidence and reproduction

Run `python build-w07-modern-role/audit.py` from this checkout. The script reads
the final compiled inventory, verifies the complete active-feature/tag roster,
checks that filter and PWM destinations have participating audible rank
sources, records controls and source hashes, and validates the five rounded
echo descriptions. `summary.json` contains the complete per-program mapping.

Relevant code is `Engine.h`, `Engine.cpp`, `ModulationLfo.h`, `FxSlot.h`,
`FxModels.h`, `CuratedLibrary.inc`, the three contributing curated files, and
the processor/editor mode and recall methods. Exact file hashes identify the
reviewed sources.

This is a source-routing audit, not an acoustic or listening measurement. An
active path establishes that a control has a sound-producing destination; it
does not by itself establish perceptual prominence or quality in arbitrary
performances. No claim of physical-instrument matching is made.
