## Why complete AU resources require the original comparisons

The [independent unchanged A51 run](../verification/a31/macos-arm64-a51-inspection.json) verifies actual archive consistency and AU executable binding. It intentionally keeps `validated_bundle_identity_established`, `run_attempt_bound` and `release_qualified` false.

The pre/post AU files contain only two executable hashes: build source and registered copy. All four recorded values equal packaged AU SHA-256 `3afb174dd4594613175b20eb0bdb06eda750508c48cc23009fb253c0dcf0d85c`. This alone says nothing about the AU's other files. The packaged AU has **eight inventory entries: four directories and four ordinary files**—`Info.plist`, the Mach-O executable, `PkgInfo` and `_CodeSignature/CodeResources`. It has no symlinks. A51 verifies the complete serialized inventory, including all four file hashes and archived modes.

The original sequence supplies the missing content connection:

1. At **12:04:39 UTC**, `Register built AU` signs **the build source** with `codesign --force --sign -`, removes the previous registered destination, copies that signed source, then executes unsuppressed `diff -qr "$AU_SOURCE" "$AU_DEST"` before recording the two executable hashes.
2. All five validator lanes run. The VST3 lane names the build-tree VST3; all four AU lanes name the registered AU destination. Their exact paths agree with A51's records.
3. At **12:08:54 UTC**, the successful package step runs the same complete-directory comparison, records the identical executable hashes, runs the inert packaging self-test, and packages the same build `Release` tree.

The exact [packager source](https://github.com/cheshmakzanoon-ops/yamaha-cs80/blob/c5549f7d095a5c5f49a5ad22ec0ccc819245d201/scripts/package-ci-artifacts.py) reads existing products, writes outside their tree, and verifies every serialized inventory entry. Its self-test writes only below `TemporaryDirectory`; it does not rebuild the actual product. There is no intervening workflow rebuild, re-sign, replacement or product-content edit after the registration copy. The original hash-output lines also match the archived hash files. Thus the full resource-content claim requires the original successful directory comparisons **and** this reviewed path/order connection to the packaged inventory.

That is not a persisted pre/post hash of every resource. `diff -qr` compares ordinary-file content and membership; it does not attest permissions, owner, ACLs, extended attributes or signature validity. The package inventory independently preserves/checks serialized modes. The absence of symlinks matters here: do not generalize this evidence into link-target identity for a different payload. Ad-hoc signing for registration is not publisher signing or notarization.

## VST3 and architecture boundaries

The validated VST3 path is the exact `build/CS80Reference_artefacts/Release/VST3/CS-80 Reference.vst3` later read by the packager. The intervening original commands validate AU and perform its comparisons; they do not rebuild or mutate VST3. The complete VST3 package inventory has ten entries. Mac CI supplies no separately uploaded validated VST3 product archive and no pre/post VST3 tree hash. Its acceptance therefore uses original source/path/order plus the complete package inventory; A51's inventory result alone cannot establish that bridge.

The original `uname -m` is `arm64`. A31 independently reads thin 64-bit Mach-O headers from all three packaged executables: CPU `0x0100000c`, bundle type `8` for VST3/AU and executable type `2` for Standalone. Generic A51/packager checks permit an advertised slice in a universal binary; this actual archive is thin ARM. Header checks are not full load-command validation or runtime proof. Standalone is not a pluginval lane and this review claims no end-user launch.

Intel must independently supply `uname -m`/payload CPU `x86_64`/`0x01000007`, its original `macos-15-intel` job and artifact names, five original successful lanes, both directory comparisons, and its own package/upload bindings. No ARM receipt or renamed file can clear that gate.
