## Static diagnosis and its limit

The frozen `LibraryAuditTests.cpp::measure()` creates a large automatic `Engine` for its musical phrase, destroys it, then creates another fresh automatic `Engine` for its stress chord. `measureAll()` invokes this function through two workers: the calling thread and an ordinary `std::thread` helper. The two Engine scopes are sequential; their sizes must not be added as two simultaneously live objects. The original GCC frame report shows that their stack storage is reused.

The [static stack analysis](../verification/a45/static-stack-analysis.json), [size probe results](../verification/a45/sizeof-results.json) and unchanged compiler stack reports establish the following in the local Linux x86_64 GCC 14.2 Release build:

| Item | `.6` source `18711f93` | Failed `.7` source `c5549f7d` | Repaired audit with frozen `.7` core |
| --- | ---: | ---: | ---: |
| `sizeof(InstrumentBody)` | 6,096 bytes | 6,496 bytes | 6,496 bytes |
| `sizeof(Engine)` | 491,976 bytes | 504,776 bytes | 504,776 bytes |
| `measure()` stack frame | 492,144 bytes | 504,944 bytes | **176 bytes** |

Each Engine contains **eight voices, two ranks per voice, and current plus previous body state per rank**: 32 body objects. The 400-byte increase per body therefore adds **12,800 bytes** to an Engine. This is not a sixteen-voice Engine and does not count the two sequential audit instances twice.

The source call chain is `measure()` → `Engine::prepare()` → `Engine::configureInternalRate()` → `ExternalModulationInterpolator::prepare()`. The final function creates an automatic `OversamplingDecimator` used to design interpolation coefficients; its independently measured frame is **20,640 bytes**. The original `measure()` frame and that reachable setup frame alone total **525,584 bytes**, before intervening frames or call overhead. The local reports also retain the 208-byte `Engine::prepare()` and 848-byte `configureInternalRate()` frames.

Apple's [Threading Programming Guide, Table 2-1](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Multithreading/CreatingThreads/CreatingThreads.html) documents a 512 KiB secondary-thread stack. Apple's [Darwin libpthread source](https://github.com/apple/darwin-libpthread/blob/main/src/pthread.c) defines its default as 512 × 1,024 = **524,288 bytes**, independently of the main thread's stack. A large automatic Engine therefore leaves inadequate margin for this setup path; even the two selected GCC frames exceed that documented budget.

This is concrete evidence of an audit portability hazard and strongly supports worker-stack exhaustion as the cause of the immediate Intel failure. **It does not identify the original faulting instruction or prove the exact native stack layout.** The original job did not retain a crash backtrace or a measured worker stack size, and local GCC frames are not AppleClang frames. The passing ARM execution does not establish the Intel frame layout. The report does not call the failure a flake, a timeout, a new-test assertion failure or a validated platform pass.

Automatic safety review stopped the proposed deliberately constrained-stack diagnostic. No constrained-stack executable, preload probe or induced-fault reproduction was run. The unexecuted preload source was removed. The diagnosis and repair verification use static inspection and ordinary tests only.

## Authorized repair

Root explicitly authorized the bounded offline-harness change after static evidence confirmed the large worker frame. The [retained patch](../verification/a45/library-audit-heap-repair.patch) changes only `tests/LibraryAuditTests.cpp` outside A45's evidence:

- Add the explicit `<memory>` include and a short rationale comment.
- In each existing scope, construct `const auto engine = std::make_unique<Engine>();` and bind `auto& e = *engine;`.
- Preserve the separate fresh phrase/stress instances and their destruction boundaries, every audio operation, both workers, every factory program, all rendered durations, thresholds and registrations.

The repaired audit source SHA-256 is `958e67fc42fa3438c5dd47425f9f4dc8012650e44d814283aa0e3d2bbc4f69cd`. Its Engine objects now live on the heap, while the measured frame becomes 176 bytes. Allocation failure still fails execution; no fallback, skip or relaxed acceptance path was added. The change is in an offline test harness and does not add allocations to product audio processing. A45 changed no Engine/DSP source, preset, calibration, CMake, workflow, parity source or remote ref.
