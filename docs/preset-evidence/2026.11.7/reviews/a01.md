# A01 — keyboard mechanism audit

Baseline: `18711f93`. Audit only; no production source changes. Temporary candidate, PCM probe, CSVs and test logs are in `/workspace/scratch/1cee5a9391a9/agent-a01/`.

## Recommended bounded fix

**Remove the arbitrary piano principal-mode damping drop between harmonics 6 and 7.** This is the strongest remaining mechanism defect found in the inspected piano, tine, reed, clavichord and harpsichord paths. The proposed change affects existing piano bodies only; it adds no presets, parameters, modes, allocations or sample-loop work.

### Source evidence

- `src/core/InstrumentBody.h:763` defines smoothly increasing base piano losses.
- `src/core/InstrumentBody.h:818–819` then adds prompt loss only when `model == piano && harmonic <= 6`. All higher principal modes escape that additional damping.
- `src/core/InstrumentBody.h:846–886` supplies a slower second course only for harmonics 1–6. Giving those low modes both prompt and aftersound components is sensible; exempting every higher principal mode from prompt damping creates an unrelated discontinuity at the storage boundary.
- At MIDI 36 / C2 and decay 1, the sixth principal damps at approximately 1.220/s and its slow course at 0.969/s, while the seventh principal damps at only 0.636/s. Thus h7 outlasts **both** h6 components.
- Six existing curated presets use the piano body: Honky Keys, Saw Pulse Piano, Soft Keys, Stage Keys, Velocity Keys and Pressure Keys (`src/core/curated/Keys.inc`). `applyHardwareTone` clears the optional body, so this mechanism is separate from the original circuit tabs.

Candidate tested in an isolated header copy:

```cpp
if (model == piano)
    loss += registerLossScale(0.25)
          * (0.78 + 0.04 * std::min(harmonic - 1, 5));
```

This keeps the original h1–h6 prompt loss exactly and extends the capped surcharge to h7+. The second-course geometry and loss, initial weights, normalization, attack, velocity law and pitch ratios remain the same.

## Causal PCM result

Probe renders the public `InstrumentBody` API at 2× host rate; Hann-window sinusoidal projections inspect the actual generated PCM, with the principal frequency including its authored stiffness. Settings: velocity 0.95, brightness 0.8, decay 1, size 1, seed 123. Early window 0.1–0.3 s; late window 2.8–3.0 s. No private modal data is read.

| Measurement, 48 kHz host | Baseline | Candidate |
| --- | ---: | ---: |
| C1 h7/h6, early | −7.164178 dB | −8.167473 dB |
| C1 h7/h6, late | +3.226401 dB | −11.479824 dB |
| C2 h7/h6, early | −7.627676 dB | −8.823682 dB |
| C2 h7/h6, late | +7.251711 dB | −10.195808 dB |
| C2 h7 early→late decay | −14.916260 dB | −31.167377 dB |
| C2 h6 early→late decay | −29.795647 dB | −29.795250 dB |
| C2 absolute peak | 0.418316 | 0.415127 |

The C2 h7/h6 rise falls from **+14.879387 dB** to **−1.372126 dB**. Across host rates 44.1/48/96 kHz, the baseline rise is +14.879384…+14.879401 dB; the candidate is −1.372129…−1.372117 dB. The h6 difference is only projection leakage from the changed adjacent partial. The diagnosis is causal: one model-gated damping change removes a large tail-spectrum reversal without altering the low course.

The expected audible effect is less isolated upper-mid ringing as bass piano notes settle. That is an inference from the measured spectral evolution, **not** an acoustic equivalence or listener-preference result. No reference piano recording or listening panel was used.

## Verification and implementation test plan

The isolated candidate already passes:

- `InstrumentBodyTests.cpp`: **2,077 checks, zero failures**, 41,062,350 generated samples. This includes existing bass h29 detail, two-stage fundamental decay, fractional-register continuity, pitch, velocity and Nyquist checks.
- `StruckBodyDynamicsTests.cpp`: **3,439 checks, zero failures**, including velocity monotonicity, spectral contrast, bounds and organ/harpsichord fixed-touch controls.

Add a rendered regression that checks C1 and C2 h7/h6 early→late change remains below +1 dB at the three host rates above; require enough absolute h6/h7 signal and verify pitched peaks against nearby off-harmonic probes. Restoring the original `harmonic <= 6` condition must fail by at least 9 dB. Repeat with several seeds and a second brightness/velocity before fixing final tolerances. Test decay control extremes using proportionally scaled analysis times, and include a non-piano PCM identity control.

For final integration, render Stage Keys and Soft Keys with their actual filters/VCA, held low notes and pedal/release phrases. Compare normalized tail bands as well as absolute level. Preserve the bright bass attack and the intended fast key damping. Do not require every neighboring partial to decay monotonically: C3's h6 has strong course-beat cancellation in a single short late window, so it is a poor sole oracle. Use C1/C2 and/or averaged windows to isolate this defect.

## Other keyboard mechanisms reviewed

Tine and reed already have different modal/even-harmonic spectra and excursion-dependent pickup harmonics (`makeTineModes`, reed `pickupPower`, `updateControls`); their existing tests explicitly exercise these distinctions. Harpsichord correctly holds strike and excitation seed fixed, with near-flat touch in its curated recipes. Clavichord has an independent tangent spectrum and losses. No equally concrete defect in those paths justified adding a speculative change to this fix. Their timbres can still merit separate listening-led refinement; this report does not claim all keyboard realism is solved.

The candidate reduces upper-piano persistence by design, so bright or synthetic piano combinations require a full preset audition. It does not add sympathetic resonance, damper noise or nonlinear string coupling. Those absent mechanisms are outside this bounded recommendation.
