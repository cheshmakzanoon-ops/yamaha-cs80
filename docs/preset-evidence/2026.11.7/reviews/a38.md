## Capacity and fractional boundaries

In [InstrumentBody.h](../../../../src/core/InstrumentBody.h), the oscillator
array remains 48 slots. Both response arrays now use the same
`maximumModes` constant, so they also contain 48 doubles. `addMode()` checks
`count >= maximumModes` before incrementing and writing. Initialization,
control response, modal rendering and rotation normalization all iterate only
over `i < count`. No new live mode insertion occurs in `tick()` or
`updateControls()`.

| Route | Captured budget / capacity | Relevant consequence |
| --- | --- | --- |
| Ah / Oo | `clamp(4400 / (bodySize * keyHz), 24, 48)`; `ceil` chooses the admitted harmonic count | Expanded modes and response histories share the 48-slot limit. |
| Piano | 24–42 principal modes, followed by six course modes | At most 48 modes; the new damping condition does not change allocation. |
| Five standard strings | Existing 24-harmonic budget | The added formant readers fit the expanded arrays. |
| Existing banjo / koto / harp | Existing harmonic allocation and material response | Material response dispatch retains priority over generic string response. |
| Other material / bar / tine paths | Existing builders and the same guarded `addMode()` | The four changes introduce no additional builder or capacity. |

For a fractional budget `n + epsilon`, harmonics through `n` retain full
coverage and harmonic `n + 1` receives `epsilon`. At the 24-mode floor, a
25th harmonic therefore starts with vanishing weight. Approaching the
48-mode cap from below brings the 48th harmonic continuously to full weight;
the clamped upper side never admits a 49th. Each positive choir weight
includes the positive vocal-formant floor, so harmonic 24 is present and the
saved breath-seed checkpoint at that harmonic is reached for the legal
parameter domain reviewed. Additional choir phase draws are then discarded
from the subsequent breath stream by restoring that checkpoint.

The following are **source-derived boundaries**, not independent runtime
mode-count measurements. Frequency refers to captured onset pitch; later
bends preserve the captured bank.

| Body size | 48-mode cap at or below | MIDI boundary | 24-mode floor at or above | MIDI boundary |
| ---: | ---: | ---: | ---: | ---: |
| 0.5 | 183.333333 Hz | 53.843587 | 366.666667 Hz | 65.843587 |
| 1.0 | 91.666667 Hz | 41.843587 | 183.333333 Hz | 53.843587 |
| 2.5 | 36.666667 Hz | 25.980450 | 73.333333 Hz | 37.980450 |

The unchanged `LowChoirSpectrumTests` exercises boundaries 24, 25, 32, 40,
47 and 48 from both sides. This sanitized run measured the same worst

passed its convergence criterion. Its upper-spectrum checks also passed the

## State initialization, reuse and existing histories

`reset()` clears the mode bank, count, model, variant, material, sample/control
countdowns, phase-refresh state, previous pitch/colour, onset and noise
histories, pickup motion, expression/motion histories and ramp flags. It
deliberately does **not** zero the response arrays or the new cached
rate-compensation coefficients. That retention does not expose an active
stale reader in the reviewed call sequence:

1. After reset, `model == off` and `count == 0`; `tick()` returns before
   updating or reading active modal histories.
2. Every non-Off accepted note rebuilds its modes. If it tracks formants,
   `noteOn()` resets the response bound and bound gain, and writes both the
   inverse response and unity gain for every index below the new count.
3. A 48-to-24 reuse leaves upper array entries unused. A later 24-to-48
   reuse initializes those newly active entries before any rendering.
4. Returning to the exact public float representation of the onset pitch
   uses `bowedResponseGain.fill(1.0)` over the whole expanded array and resets
   the common bound gain. Generic string bending therefore does not require
   resetting the note's decay, excitation, contact, onset or phase history.
5. Nontracking bodies do not read response histories. Their later replacement
   with a tracking body takes the same initialization path above.

The shared fixed-formant functions retain positive floors. For the reviewed
finite legal pitches and body sizes, onset inverses are finite and positive.
The common gain correction remains bounded by the captured absolute modal
sum; host antialias fades, per-partial onset and pickup factors still apply
before the existing 16-sample interpolation. This concerns the modal sum,
not an assertion that added air/contact texture has exactly the same ceiling.

The piano correction only extends the existing positive principal-partial
loss surcharge, capped at the h6 amount. It does not alter the six slower
course entries, their phase draws, or onset histories. The generic-string
correction reuses the original body expressions at onset and selects the
existing material functions first for banjo, koto and harp. The noise change
recomputes its two independent gains in `prepare()`; reset and note-on retain
the correct gains for that prepared rate while clearing the filter history.
At 96 kHz internal rate, the explicit `1.0` noise gain and `0.012` flutter
depth preserve the reference operation's constants.

### Engine lifecycle boundary

The surrounding [Engine.cpp](../../../../src/core/Engine.cpp) and
[Engine.h](../../../../src/core/Engine.h) retain these responsibilities:

| Event | Observed source behavior |
| --- | --- |
| Rate preparation | Prepares both current and previous bodies and filters; clears handoff count. |
| Engine reset or hard panic | Resets both body instances and their filters; clears handoff count. |
| Accepted note on an audible reused rank | Copies the complete current body into the previous-body value before initializing the incoming note. Both response arrays and noise/onset histories participate in the default value copy. |
| Normal release | Calls the rank amplitude/filter envelopes' `noteOff()`; it does not call a body reset or rebuild. Captured body history continues under the existing release envelope. |
| Outgoing handoff | Advances the copied previous body at its retained pitch, colour and pressure during the existing 3 ms handoff. |

InstrumentBody has no separate note-off method. The new public-API probe
therefore tests value-copy continuation and reuse, **not** an invented body
release API. Actual Engine release, pedal and host-lifecycle execution remains
with root's native tests. Existing Engine tests already contain release,
captured-articulation, pedal and handoff contracts; A38 did not rerun them or
build a second Engine library.

## Reproduction and limits

From the repository root, with the reviewed source checked out:

```sh
python3 docs/preset-evidence/2026.11.7/verification/a38/run_sanitizers.py
python3 docs/preset-evidence/2026.11.7/verification/a38/run_sanitizers.py --lifecycle-only
```

The runner rewrites only A38's verification logs/receipts and places binaries
in `/tmp/cs80-a38-1cee5a` unless `--scratch` is supplied. Five binaries occupy
about 2.3 MiB. No shared build, production file, fixture, threshold, CMake file,
workflow or git reference was changed by A38.

Leak detection is explicitly disabled because the existing A06/A07 evidence
records this host's ptrace-supervised LeakSanitizer limitation. A38 makes no
leak-checking claim. These are GCC/Linux ASan and UBSan results; they do not
qualify other compilers or native plugin hosts, exercise concurrency, establish
all uninitialized-state properties, or prove every possible input safe. No
invalid-input fault probe, constrained-stack experiment, full plugin build,
new all-family capture or repeated CPU benchmark was used. A11's combined CPU
evidence was reviewed for scope and source identity, not rerun or promoted to
a whole-engine callback guarantee.
