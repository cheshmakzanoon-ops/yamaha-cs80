## Protecting a running source build

**A docs-only `[skip ci]` push does not cancel the existing build through this concurrency policy.** GitHub's [skip documentation](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs) says the annotation prevents push/pull-request workflows from being triggered. Its [concurrency documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) ties cancellation to another job/run entering the same concurrency group. With no replacement build jobs, there is no same-group cancellation event.

This repository supplies a direct observation: `18711f93`, whose message ends `[skip ci]`, was committed at **10:49:20 UTC**. The authenticated run collection for that exact SHA returned **zero runs**, and `195fb62` jobs subsequently started at 10:50:56, 10:55:09 and 11:00:09 UTC.

The distinction is the skip annotation, not “docs-only” by itself. Current `build.yml` excludes only `scripts/inspect_circuit_sources.py` and `.github/workflows/circuit-inspection.yml`; an ordinary documentation push starts a new build and can cancel unfinished same-branch jobs. Linux, Windows and each Mac target have separate groups. Their dependent validator jobs also have groups.

After freezing source, agents can continue writing reviews and retained evidence. Changes to production code, CMake, compiled inputs, test definitions or the capture script mean a new source must qualify. A skip annotation must not be used to pass off those changed inputs as the already-built source. Some documentation is compiled or authenticated by tests; protect those exact inputs too.

Manual builds have run-ID-specific groups and are insulated from ordinary main-push cancellation. However, the old publisher explicitly requires `event == push`, so a manual run cannot silently substitute for its contract.
