# A43 — Installation and factory-reload user flow

## Decision and scope

**The source supports the documented explicit factory-load flow. Old saved controls can mask the cumulative recipe changes unless the user loads the factory entry and plays fresh notes.** The current guides already explain this distinction. The main publication improvements are to put that step in the initial install/first-sound path, distinguish toolbar arrows from Library navigation, and expose the live download page prominently.

This is a **source and documentation audit**, not an actual installation, DAW session, browser interaction, listening assessment, or native product execution. No product, test suite, packager or archived binary was executed. No current remote CI status or public download route was queried. The assignment supplied build **45397189410, attempt 1** as running; this review does not turn that checkpoint into a final result.

Frozen binary source: `ee0dabcacb4cdff93f8803844f60348e0ceda6ed`, tree `17115913cbb29157bd00539485bcc5f38b57219c`. The inspected main documentation checkpoint is `39811916`; its full SHA is in the [readset receipt](../verification/a43/source-readset.json). All **96 inventoried source/documentation files** are byte-identical between those checkpoints. The source, factory recipes and plug-in tree remain separate from the later release qualification. The prior `c5549f7d` Mac archive evidence belongs to that prior source and is not relabelled as acceptance of the `ee0dabca` build.

Only this review and `verification/a43/` were written. Main README/guides, production source, presets, workflows, shared tests, historical archives and other workers' files were left alone. There was no staging, commit, push or additional agent.

## Exact Library behavior

| User action | Source behavior | Consequence for an update |
| --- | --- | --- |
| Open **LIBRARY**, refresh, search or restore a selected row | Refresh/select-current operations use a restoration guard. Opening captures the current sound for REVERT. | Opening Library and seeing a familiar name does not prove the new factory vector is sounding. |
| Choose **FACTORY LIBRARY** | Scope filters out user files; other active filters/search can still restrict results. | A same-name user patch cannot be mistaken for the factory entry within this scope. If a sound is hidden, **CLEAR ALL** first, then choose FACTORY LIBRARY again: CLEAR ALL resets the scope too. |
| Select a row with **AUDITION** off | Selection changes without loading. AUDITION starts false but the user's preference persists. | Press LOAD/RELOAD. Do not assume a click changes the sound. |
| Select a different, not-already-loaded row with **AUDITION** on | Calls `loadSelected()` during explicit selection. | It normally auditions the selected entry. |
| Click a row already marked loaded, including an edited factory sound, with AUDITION on | The `!isLoaded(*entry)` guard avoids another load. `isLoaded` compares the stable loaded key, not the complete current parameter vector. | Old/edited values can remain. Turning AUDITION on also uses that guard. |
| Press **LOAD** or **RELOAD** | Both labels use the same button callback, then `loadSelected → loadEntry → loadFactoryPreset` for a factory entry. There is no “already loaded” guard on this explicit path. | Applies the current bank vector even if the same name/index is already active. Visible RELOAD does not mean a different operation. |
| Enter on the result list, or double-click a result | Calls `loadSelected()` directly. | Same explicit factory-load behavior. Do not generalize Enter to the save-name field, where it saves instead. |
| Press **REVERT** | Restores the captured opening values, sources, memories, modern configuration and metadata. A new Library opening captures a new baseline. | It can restore the older recipe. It is not “restore latest factory.” |
| Close Library | The close callback hides the browser; it does not invoke REVERT. | The loaded sound remains active. Save the project if that selection should persist. |
| Recall an old session, user patch or A/B slot | Restores stored sound/control state; session metadata does not call factory recall. | A factory-looking name is not evidence of the new recipe. A/B can restore earlier settings after a successful load. |

The load status is exactly `Loaded "<preset name>".`. The visible button becomes **RELOAD** when the selected entry is marked loaded; its accessible title remains **LOAD**. Session restoration can retain a factory-looking name with unknown runtime provenance, so **LOAD or RELOAD, whichever is shown** is the correct instruction. These details are in `PresetBrowser.cpp` 3582–3635, 3667–3706, 3734–3765, 3830–3842, 3907–3922 and 4040–4124; `PresetBrowser.h` 216 and 298–315; and `PluginProcessor.cpp` 737–746 and 1677–1685, retained in the [source evidence](../verification/a43/source-evidence.md).

Factory recall resets the hardware sources to PANEL and writes every non-setup, non-retired sound parameter through `applyValues`. It does not hard-stop all old notes or recreate a complete processor. Body model, partial decay, resonant size, variant and material are passed to the body at note onset. Mix and brightness are read live. Releasing keys and the sustain pedal, then playing fresh accepted notes, avoids judging a new recipe through a previous ringing body's captured settings. The code's normal voice-admission limits still apply. See `PluginProcessor.cpp` 704–724 and 840–855, `Engine.cpp` 999–1008, 1539–1551, 1583–1590 and 3284–3306 in the [source evidence](../verification/a43/source-evidence.md).

The cumulative `.4`→`.7` work revises the existing musical recipes, with **523 total programs and no additions**; `.7` itself keeps `.6` parameter vectors and changes rendering. An older body-enabled saved patch can therefore sound different on the new engine even before its controls are reloaded. Conversely, retaining a `.4` recipe does not demonstrate that the cumulative current recipe was heard. The current preset guide already states both distinctions at 432–478, consistent with [A27's prior state/recipe review](a27.md). Preserve this distinction in final wording.

These paths and constraints are retained at install-guide 112–148 in the [excerpts](../verification/a43/source-evidence.md); external vendor documentation was not fetched during this source-only assignment.

**Keep the entire VST3 folder.** On Windows the nested native file is itself named `CS-80 Reference.vst3` under `Contents/x86_64-win`; it is not the complete bundle to copy. Linux similarly has a `.so` under `Contents/x86_64-linux`. Mac app/AU/VST3 bundles contain metadata and their native executable. The source packager requires nonempty binaries, rejects unsupported/escaping links and Windows reparse points, and preserves Unix modes and safe internal bundle links. Its Unix binary admission checks require execute bits. Use the inner tar to preserve these properties; do not translate this into an instruction to change permissions on every file or loosen system security. These are source-defined packaging safeguards, not evidence that a user extraction was exercised.

Choose a Mac package for the **host process architecture**. The `macos-15` label is the ARM workflow artifact; `macos-15-intel` is x86-64. An Apple Silicon machine can run a differently architected host, but the existing source guide expressly does not qualify emulation layers. No universal binary, ARM Windows build, Linux ARM build, AppImage/static Linux runtime or automated installer is advertised by this package contract. The guide correctly notes compatible Linux libraries, separate native Mac packages, optional system-directory permissions, duplicate plug-in scan risks and signing/notarization limits. A43 did not install or alter any system settings.

## Body controls and sound-selection pitfalls

`PluginProcessor.cpp` 424–470 exposes two original host groups, **Instrument body I** and **Instrument body II**, each with model, mix, brightness and partial decay. Size, variant and material are appended parameters outside those original groups to retain established host ordering. The exact registered names for rank I are below; rank II substitutes `II` for `I`.

| Control | Exact rank-I registered host name | Change timing |
| --- | --- | --- |
| Model | `Body I model (next note)` | Next accepted note |
| Mix | `BODY I MIX` | Live |
| Brightness | `BODY I BRIGHTNESS` | Live |
| Partial decay | `BODY I PARTIAL DECAY (NEXT NOTE)` | Next accepted note; relevant to struck models |
| Resonant size | `BODY I RESONANT SIZE (NEXT NOTE)` | Next accepted note |
| Variant | `Body I resonator variant (next note)` | Next accepted note |
| Material | `Body I material (next note)` | Next accepted note |

The host can choose its own display/case/truncation/group presentation. The source supplies **14 controls**, **204 core parameters**, and **310 host positions**, including retained compatibility positions; this is not a claim that all 310 positions are automatable. The [readset receipt](../verification/a43/source-readset.json) records a bounded scan of all plug-in `.cpp`/`.h` files: body-symbol matches occur in the parameter registration, evidence help and generic value-formatting code, not a dedicated Studio body page. The processor's editor constructor returns the custom editor. No actual host generic-parameter UI was opened.

Factory Library selection is also important because hardware tone tabs are separate electrical source recipes. Bodies require PANEL sources (`hardwareSources[ch] == 13`); they are suppressed on hardware-tone and memory paths. Pressing the physical-panel **E. PIANO** tab is therefore not the same action as loading **Tone I: E. Piano**, **Analog Piano** or **Electric Piano I** from Library. The existing guide is correct on this point. Aftertouch-only **Pressure Lead** and **Electric Leads 136** are another expected-silence case already documented; do not treat a zero-pressure comparison as a failed install. Sources: `Engine.cpp` 999–1008, `PluginProcessor.cpp` 424–470, `Params.h` 505–525 and the preset-guide excerpts in [source evidence](../verification/a43/source-evidence.md).

## Link and claim review

The text-only [link inventory](../verification/a43/link-audit.json) checked **186 repository/same-document targets** across README and the three guides. It found **zero absent source paths** and **zero unmatched heading fragments** with its documented heading parser. This is a source target check, not HTTP testing. All external links, including nightly.link and vendor sites, remain unrequested by A43.

The packager intentionally keeps links among the three bundled guides local, pins other repository links to the full source commit, and leaves existing absolute main/external URLs unchanged. Thus flattened archive guides do not accidentally point to missing `../README.md` files. Their early relative “current” links become valid **historical** source links, which explains the live-pointer recommendation above. Historical `.4` installation/audition IDs and “13 validator lanes” are accurate historical claims in their section; the final `.7` acceptance contract separately requires its current lane count. Do not globally replace history with current labels. [A30](a30.md) already records the 15-lane current contract and its source-document supplement limits.

No named-DAW compatibility promise was found in the inspected guides. They explicitly separate CI/native/validator evidence from interactive installation and arbitrary DAW compatibility, and distinguish source-time snapshots from completed release documentation. Keep that distinction in the final delivery: “archive/inventory/hash/architecture verified” is evidence for the packages; “installed and played in a specific DAW” requires a retained real session for that host, OS, architecture and format. Screenshots, source behavior and prior-source validation do not fill that gap.
