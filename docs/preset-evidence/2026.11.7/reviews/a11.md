# A11 — combined body CPU review

## Verdict

**No broad high-note choir regression is reproduced. Proceed with source-freeze integration.** The earlier separate-process MIDI-60 estimate near 2× is unsupported by this controlled comparison. Low choir incurs the intended extra oscillator work; generic strings incur additional formant work during continuous pitch changes. No production change was made by A11.

## Scope and method

One GCC 14.2 executable contains three independently namespaced header snapshots:

- **OLD:** `18711f93`, before the four changes.
- **PRE:** A07's exact pre-choir snapshot, including A04 piano damping, A05 cached noise gains, and A06 generic string formants.
- **NEW:** the combined working header, SHA-256 `d825961c532e7bd5d27d3e19cf3bd2233736fa9c8072822cbb6cb3c0b07d40dc`.

All compile together with `-std=c++17 -O3 -DNDEBUG`. Snapshot preparation changes only namespaces and adds an unused-in-timing mode-count accessor; production files remain untouched. Complete input hashes and the OLD-to-PRE patch are retained.

Each of 24 cases compares OLD/NEW and PRE/NEW using five deterministically shuffled **ABBA or BAAB blocks**, ten timed runs per version. Every run creates the same voice, prewarms 32,768 samples, then measures 131,072 samples. All three versions receive an additional warm-up before comparisons. Preparation, note-on, buffer allocation, PCM hashing, and CSV output are outside timing. A preallocated output buffer preserves the rendered result; every case/version repeats its hash exactly.

The process is pinned to available CPU 0. Both `CLOCK_PROCESS_CPUTIME_ID` and monotonic wall time are recorded. Host rate is 48 kHz; internal rate is 96 kHz, with selected 384 kHz controls. Static pitch uses the exact float representation of the original double-computed onset frequency. Bend cases use a precomputed continuous 4 Hz, ±2-semitone trajectory. Velocity, brightness, pressure, seed, size, and buffers are identical across versions.

## Results

The table isolates A07. CPU times are medians in ns/internal sample; ratios are medians of the five within-block NEW/PRE mean ratios, so they need not equal the quotient of the displayed medians.

| Choir case | PRE→NEW modes | PRE ns | NEW ns | Paired ratio |
|---|---:|---:|---:|---:|
| Ah MIDI 36 | 24→48 | 55.63 | 100.07 | 1.847 |
| Ah MIDI 48 | 24→34 | 56.30 | 72.83 | 1.226 |
| Ah MIDI 60 | 24→24 | 52.22 | 52.51 | 1.011 |
| Ah MIDI 84 | 24→24 | 66.67 | 65.51 | 0.996 |
| Oo MIDI 36 | 24→48 | 59.68 | 110.73 | 1.905 |
| Oo MIDI 60 | 24→24 | 56.85 | 56.79 | 0.983 |
| Ah MIDI 60, 384 kHz | 24→24 | 55.23 | 55.62 | 1.039 |
| Ah MIDI 36, bend | 24→48 | 84.95 | 155.48 | 1.852 |
| Ah MIDI 60, bend | 24→24 | 78.44 | 79.82 | 1.023 |

The 24-mode choir cases also retain identical PRE/NEW PCM hashes. Larger response arrays do not produce the alleged high-note slowdown. Low-note ratios remain below the 2× oscillator-count increase in these median comparisons, including continuous bends.

Across the five standard string models, OLD→NEW fixed-pitch paired ratios are **1.013–1.073**; continuous-bend ratios are **1.119–1.313**. PRE→NEW bend ratios are **0.961–1.011**, isolating the added bend cost to the earlier formant correction rather than A07. The correction evaluates rational body responses only at pitch-changing control boundaries. Static string hashes remain OLD/NEW-identical.

Body size is **6,096→6,112→6,496 bytes**: A05 adds 16 cached-coefficient bytes; A07 adds 384 response-history bytes. The sample bank remains fixed at 48 slots. Global C++ allocation hooks report **zero allocations in all 960 measured sample loops**; note-on allocation is outside this measurement. Piano and noise-control timings show no consistent large regression.

## Limits and retained evidence

Process CPU timing removes descheduling time, but cannot remove host frequency changes or shared-resource contention. Individual paired ranges remain noisy; the unchanged organ control even produces an implausible apparent speedup in one comparison. Wall/CPU ratios reach **1.822**. Accordingly, these data reject a broad near-2× high-choir regression; they do not establish precise single-digit overhead percentages or whole-engine callback capacity.
