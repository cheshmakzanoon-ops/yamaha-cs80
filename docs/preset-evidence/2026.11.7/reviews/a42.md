## Saved controls, missing data and undo

`normaliseRestoredState()` creates a detached copy before APVTS replacement.
It visits every core parameter and every programmer parameter. Missing or
nonfinite body values take their declared default; finite values are clamped
to the host range, and discrete choices are snapped. The final matching
child remains authoritative and earlier known-ID duplicates are removed.
This agrees with the inspected JUCE `updateParameterConnectionsToChildTrees()`
loop, which binds children in document order. Completing the detached tree is
necessary because absent JUCE parameter children otherwise preserve live
parameter values. The production child index preserves the stringified-ID and
ordered-match semantics of the prior scans.

The older-file behavior is consequently specific and cumulative:

| Serialized controls available | Restored body contract |
| --- | --- |
| Before body controls | Both models/mixes off; brightness 0.5, decay/size 1, Variant/Material Standard |
| First eight body controls | Preserve those eight; both Sizes 1, Variants/Materials Standard |
| Published `.4`, ten body controls | Preserve all ten; both Variants and Materials Standard |
| `.5`, twelve body controls | Preserve all twelve; both Materials Standard |
| `.6`/`.7`, fourteen body controls | Preserve all fourteen valid stored values |

Both `setStateInformation()` and `loadUserPreset()` call this same normalizer.
The user-file loader then preserves only three explicit live session settings:
oversampling, listening-output jack and tuning mode. None is a body field.
Session restore additionally reads its studio/tuning and inactive A/B data.
The schema marker remains **4**; missing body fields do not depend on incrementing
that marker. Retired policy fields normalize to `sourcePerformance=1` and
`parityMode=0`. The special main-loader fallback for missing/invalid Original
SUB mode remains **0**, distinct from its fresh-instance default.

Inactive A/B storage serializes all `P_numParams` controls. Its reader starts
from incoming saved data and declared fallbacks, never the receiving active
slot's values. It likewise clamps/snaps body values and defaults absent
Variants/Materials to zero. Its generic declared-default rule should not be
misdescribed as reproducing the main loader's special Original SUB fallback.
Valid but incompatible model/Variant/Material combinations remain saved
controls: `InstrumentBody::noteOn()` applies compatibility to the generated
sound without rewriting the stored choices.

Undo tracks every actual ranged host parameter. All fourteen body controls
therefore participate in the existing balanced-gesture and undo/redo path.
`copyStateForSave()` reads the current denormalized atomics into a detached tree,
including all matching duplicate children, without inserting unrelated host
automation into the latest user gesture. Saving on a background thread is
covered by the existing session-undo fixture. As documented in the source,
these are individual atomic reads, not a transaction across concurrently
changing parameters.

## Programs and the distinction between stored controls and current audio

Independent comparisons of the authenticated retained inventories reproduce
the same **523 addresses, names, categories and order** across `.4`, `.6` and
`.7`. Final `.7` and `.6` inventories are byte-identical after changing only the
revision string: all **106,692 values**, tags and descriptions are retained.
The final ordered binary32 values digest is
`aedb533d123874448b4df31f3c25aa7cb109d4109c6dc22ee9548ebcdeb42273`.
This is a fresh comparison of retained inventories, not a new bank capture.
[Catalogue binding](../verification/a42/catalogue-binding.json) ·
[A12 complete bank evidence](a12.md)

`setStateInformation()` restores saved values and metadata; it does not invoke
`loadFactoryPreset()`. `setPresetMetadata()` clamps an invalid factory index
without loading that recipe. The host's `setCurrentProgram()`, an explicit
factory browser LOAD/RELOAD, and accepted MIDI Program Change instead reach
the current factory vector at the stable address. The explicit factory path
preserves its existing physical-setup exclusions and resets sources to PANEL;
body controls remain part of the sound being recalled. MIDI bank conversion
and the hardware tone names retain exact published source.

Thus a saved edited patch keeps its serialized controls. Applying cumulative
recipe changes since `.4` requires explicit factory recall; `.7` adds no recipe
value edit over `.6`. A saved body-enabled patch still renders with the newer
DSP. Piano partial decay, noise, string-formant and low-choir corrections can
change that audio while its saved controls remain identical. The A27 Init/core
results and A40 sound-source continuity retain their stated scopes; neither
promises old body-enabled PCM identity. [A27](a27.md) · [A40](a40.md)

### Retained VST3 Program limitation

The documented controller dependency of **VST3 wrapper Program changes sent
only through the processing parameter queue remains unresolved**. Pinned
JUCE's controller-side `ProgramChangeParameter::setNormalized()` calls
`setCurrentProgram()`; the processing queue follows its distinct parameter
write path. The product's wrapper adaptation and parameter-automation source
are unchanged. Nothing in this revision repairs that earlier observed
limitation, and A42 did not repeat its runtime diagnostic.

The direct JUCE MIDI Program Change fixture and
`Vst3AutomationProgramBoundaryTests.h` exercise different paths; the latter
explicitly uses accepted legacy-MIDI events. Their success cannot qualify
processing-queue-only wrapper Program automation, universal sample-accurate
program switching, or every DAW. The prior disclosure must remain in release
wording. [Original native-recall and Program-queue qualification](../../../PRESET_REFINEMENT_2026_11_1.md#native-recall-and-host-program-qualification)
