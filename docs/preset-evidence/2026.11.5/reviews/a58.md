# A58 — Adversarial release-gate review

## Checkpoint outcome

Two concrete preparation gaps were found before any final platform acceptance:

1. **Raw native/validator parser observations were not bound to the actual
   ZIP/API hashes in the prepared Windows and Mac binders.** Those binders
   checked the acquired archives and consumed parser results, but did not join
   the parser's own archive identity to the bytes being accepted.
2. **The Windows consumer receipt check was conditional on optional compiler
   sidecars.** A36 inspects the exact original VST3 download receipt when the
   `.exp`/`.lib` pair is present. The prepared A49 binder did not independently
   require that receipt for a sidecar-free input archive.

The coordinator accepted both corrections. Their implementation belongs in
fresh c76 evidence copies, not the retained db6b checkpoints. No original
checkpoint or historical hash record was changed by this review.

This is a preparation checkpoint. **No c76 native, validator, installation,
audition or whole-release acceptance is asserted.** The actual platform records
will be reconciled after they exist.

## Concrete correction and bounded probe

The [closure instructions](../ci/source-c76ad28/release-gate-audit/closure-instructions.md)
provide exact size/digest assertions and unconditional Windows original-step
receipt/digest/completion checks. They also require any A36 consumer-log digest
to match the actual original log used by A49.

The new [independent checker](../ci/source-c76ad28/release-gate-audit/bind-parser-archives.py)
takes explicit source, run, attempt context, target, actual ZIPs, artifact API
receipts and raw parser observations. It snapshots bounded regular files,
rejects duplicate JSON keys/nonfinite constants, verifies ZIP/API identity, and
matches both parser archive records and every parsed input-member hash against
the same in-memory ZIP bytes. It pins the unchanged historical parser and
refuses to overwrite a prior report. It executes no downloaded product.

A deliberately small [inert-fixture probe](../ci/source-c76ad28/release-gate-audit/test-parser-archive-binding.py)
passed **12 methods: one positive and eleven rejection cases, zero failures,
errors or skips**. Rejections cover stale archive digest/size, a substituted
validator ZIP with coherent new API metadata, stale member records after a
coherent outer ZIP update, wrong source/artifact name, duplicate target,
missing archive provenance, altered raw release scope, missing JUCE record and
a stale preserved-attempt digest.

## Assessment of the remaining chain

all required steps, exact source/run/attempt, upload IDs/digests/sizes/times,
complete native rosters and all fifteen added CTests, actual JUCE provenance,
strictness/program/GUI/seed markers and unsuppressed source exit propagation.
Their install and payload helper reports already have explicit actual-byte
bindings. F1 adds the missing equivalent join for parser reports.

The Linux original-evidence binder deliberately leaves native content, validator
results, retry eligibility and payload equality outside its scope. That is an
honest boundary, not a passing platform gate. Its final composition must run the
same A58 archive/member binding and independently inspect every retry. A normal
exit status 139 and a raw signal return code −11 are distinct observations.
Neither a later diagnostic run nor clean SUCCESS text replaces the required
original lane and normal final child exit.

Mac resource identity depends on original successful full AU directory
comparisons before and after validation, the reviewed unsuppressed workflow
and unchanged source/package paths. Executable hash pairs alone do not bind
resources. The prepared Mac binders preserve that distinction. Windows/Linux
payload equality must cover every selected VST3 bundle member; only the known,
format-checked Windows compiler sidecar pair can be excluded from that selected
bundle under the existing A36 contract.

The audition verifier and its A53 binder already connect the exact content
report to actual ZIP bytes, final source/tree/run and the independently retained
full inventory. Its expected 171-clip roster remains an expectation until the
new archive is actually produced and inspected.
