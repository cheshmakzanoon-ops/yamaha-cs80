## Corrected golden-fixture dependency

`tests/PanelEditorTests.h::testGoldenImages` starts from factory program 0,
**Tone I: String 1**, then explicitly pins visible controls to the existing
historical layout fixture. Six revised VCA/touch controls were not originally
included in those pins. They would move visible sliders despite the fixture's
stated intention to remain independent of factory revoicing:

| Control | Historical fixture value | Revised factory value |
|---|---:|---:|
| Rank I fixed VCA level | 0.55 | 0.22 |
| Rank I initial level | 0.34 | 0.70 |
| Rank I aftertouch level | 0.22 | 0.26 |
| Rank II fixed VCA level | 0.50 | 0.18 |
| Rank II initial level | 0.28 | 0.62 |
| Rank II aftertouch level | 0.18 | 0.24 |

Both retained preceding inventories agree on those historical values. Root
added the six explicit `setParamValue` calls alongside the existing pins. A27
re-read the resulting source and checked all six exact assignments. The
comparison of the older inventory with the current program found no other
uncovered visible control difference: the remaining unpinned differences are
body controls, for which the custom main editor has no dedicated widgets.
Program 0's master trim remains **1.000** in both calibration passes.

The golden PNGs remain byte-identical to the starting commit. Image masks,
pixel tolerances, block tolerances, rendering comparison and strict-platform
selection were not altered. This is a correction to the frozen test input,
not approval of a newly rendered image. The native Linux golden comparison
must still establish the actual pixel result.

## Executed formatter/parser diagnostic

A private diagnostic extracted the production helper definitions,
`formatParamValue`, `ReadNumber`/`readNumber`, and `parseParamValue` directly
from `src/plugin/UiComponents.cpp`. Their bodies were not rewritten. It
compiled them against the pinned JUCE 8.0.11 `juce_core` sources and the current
`Params.h`/`InstrumentBody.h`, independently of the full native editor binary.

The diagnostic passed **108 checks, zero failures**, with process exit 0:

- Both ranks display and parse all five exact variant names.
- Trimmed uppercase variants restore the same choice.
- Unique prefixes `Sta`, `Xylophone`, `Ste`, `Choir a`, and `Choir o` resolve to
  Standard, Xylophone bar, Steelpan shell, Choir ah, and Choir oo respectively.
- Ambiguous `St` and `Choir`, single-letter `S`, empty text, trailing garbage,
  numeric choice indexes, NaN and Inf reject without modifying the output value.
- All twenty published Model names on both ranks still round-trip exactly.

The generic parser already recognizes the new 0–4 integral choice range; the
new formatting cases provide nonnumeric names, so numeric values cannot fall
through as a continuous control. The new tests in `TypedValueUnitTests.h`
exercise the intended exact-name, case, ambiguity and nonmutation behavior.
This extracted diagnostic covers string/choice logic, not native widget
attachment, event delivery, focus or actual DAW automation.

## Other reviewed contracts

The main snapshot startup checks compare every parameter with the actual
current startup recipe rather than embedding its old values. Its physical
round-trip loop uses `P_numParams` and now classifies both variants as discrete,
matching JUCE choice snapping. The loose `factory bank >= 200` and minimum
historical host-count assertions are not array bounds; complete bank/parameter
identity checks exist separately.

`InstrumentBodyHostTests.h` covers all twelve stored body controls, missing
variant defaults for sessions/user files/inactive A/B slots, and all four
nonstandard variants on both ranks. Its next-note tests require an unchanged
sounding note and an audible change on the next accepted note. The raw
serialization fixtures intentionally permit incompatible model/variant pairs;
preserving their selected controls is distinct from the DSP's Standard fallback.

The preset search and identity fixtures use isolated temporary user files and
dynamic factory identities. They do not assume the former modern-tag count or
old descriptive prose. `PluginEditor.cpp` and `PresetBrowser.cpp` remain
unchanged from the starting commit. Their controls and geometry were not
expanded by this revision; the DAW's generic parameter list exposes the new
named choices, as the preset guide states.
