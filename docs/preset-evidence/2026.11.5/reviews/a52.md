## Parameterized original-evidence binder

[bind-linux-original-evidence.py](../ci/source-db6b5a7/linux/bind-linux-original-evidence.py)
is prepared and **syntax-checked only**. It accepts explicit source, run,
attempt and producer identifiers, so it can inspect a future execution without
relabeling this source checkpoint. It requires authentic original API/log inputs
and the four actual ZIPs. It checks source/run/attempt, successful required
producer/consumer steps, original upload ID/name/size/digest/time, API ZIP hashes
and retention, and the consumer's exact downloaded VST3 receipt and digest.

Its output intentionally keeps **`platform_qualified: false`** and
**`release_qualified: false`**. It does not replace archive-member inspection,
native parsing, lane/retry review or complete payload identity. No downloaded
product is executed. No passing binder report was generated at this checkpoint.

Example invocation, using the actual replacement identifiers and fresh output:

```sh
python3 docs/preset-evidence/2026.11.5/ci/source-db6b5a7/linux/bind-linux-original-evidence.py \
  --repo /absolute/path/to/yamaha-cs80 \
  --source ACTUAL_FULL_SOURCE_SHA \
  --run-id ACTUAL_RUN --attempt ACTUAL_ATTEMPT \
  --producer-job-id ACTUAL_LINUX_PRODUCER \
  --evidence /absolute/path/to/actual-linux-evidence \
  --downloads /absolute/path/to/actual-linux-downloads \
  --out /absolute/path/to/fresh-original-binding.json
```

The evidence directory must contain `run-attempt-api.json`, `jobs-api.json`,
`artifacts-api.json`, `producer-job.log`, `validator-job.log`, and individual
`install-api.json`, `vst3-api.json`, `test-evidence-api.json`, `pluginval-api.json`.
The download directory uses matching `install.zip`, `vst3.zip`,
`test-evidence.zip` and `pluginval.zip` names. These are required future inputs,
