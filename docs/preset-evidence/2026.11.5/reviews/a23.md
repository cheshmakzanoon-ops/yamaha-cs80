# A23 — DSP edge conditions, isolation and real-time review

## Result and scope

No blocking defect was found in the new strike normalization, Xylophone/Steelpan/vocal variants, or captured articulation code. This is a bounded software safety and routing review. It is not a native-host qualification, CPU performance benchmark, acoustic-equivalence assessment, or exhaustive proof over arbitrary event sequences.

The review compared the working source with `8685e9ed39d6347b67401da7590b7e1e8e95472d`. It inspected `InstrumentBody.h`, `InstrumentBodyVariants.h`, `BodyArticulation.h`, the changed Engine integration, and the existing body, vocal, variant and articulation tests. No production file or shared build directory was modified.

## Executed endpoint probe

A private standalone C++ probe was built with GCC 14.2 using:

```text
g++ -std=c++20 -O1 -g -fsanitize=address,undefined \
    -fno-omit-frame-pointer -D_GLIBCXX_ASSERTIONS -Isrc \
    /tmp/cs80-a23/edge.cpp -o /tmp/cs80-a23/edge
ASAN_OPTIONS=detect_leaks=0 /tmp/cs80-a23/edge
```

The first attempt reached a LeakSanitizer runtime error because this environment uses ptrace. The successful rerun disabled **only leak detection**; AddressSanitizer, UndefinedBehaviorSanitizer and libstdc++ bounds assertions remained enabled. LeakSanitizer results are not claimed.

The probe exercised:

- **16,038 articulation profiles:** every integer model from −1 through 20, crossed with nine note, velocity and mix inputs: 0, 1, −1, 127, NaN, positive/negative infinity and positive/negative `FLT_MAX`. All attack/decay/release results were finite and inside the authored bounds. Off, invalid models, Organ and zero/nonfinite mixes retained exact `{1,1,1}` profiles.
- **1,620 new-variant bodies:** all four nonstandard variants, output rates 8/44.1/48/96/192 kHz at twice-rate internal processing, and the same nine note/control inputs. Velocity, brightness, loss and size were varied together through those malformed and endpoint inputs. Each body received 1,024 samples with a pitch change every 17 samples, cycling zero, negative, NaN, infinity, the smallest positive float, `FLT_MAX`, low/high MIDI frequencies and both sides of the host-rate modal cutoff.
- **180 model/variant compatibility pairs:** all twenty valid models crossed with variants −2,147,483,647, −1, 0–5 and 2,147,483,647. Each selected pair was compared sample-for-sample with its independently selected compatible fallback for 2,048 samples, including a two-octave upward change halfway through.
- Intercepted C++ `new`/`new[]` calls while preparing, striking and processing those bodies. Source inspection separately found no direct `malloc`, allocation-owning container, lock or I/O addition in the changed DSP paths.

Actual output:

```text

```

The reported sample count covers the endpoint body sweep; the 368,640 additional sample pairs in the compatibility comparisons are separate. Invalid/nonpositive frequencies returned exactly zero. No sanitizer diagnostic appeared in the successful run, and its process exit was zero.

A second private probe linked an immutable copy of the current `libcs80_core.a`. It reused the existing Engine test fixture and compared every new variant with body-off settings on **all fourteen source selectors**, including both ranks, simultaneous MIDI 36/84 notes, and onset/release renders.

```text

```

All hardware and memory source selectors 0–12 were exactly sample-identical to the body-off counterpart through onset and release. PANEL selector 13 differed for each material/vowel variant. This checks the new variant routing directly instead of inferring it only from the original piano isolation test.

The existing `performanceReleaseAndPedal()` and `isolationAndPartition()` articulation subtests were then compiled and executed in a private wrapper against the same copied core library:


These cover unscaled KEY RELEASE and MASTER SUSTAIN timing, CC64 hold/pedal-up behavior, sustain cancellation without an envelope discontinuity, exact neutral behavior at zero body mix, live timing refresh, block/batch partition equality and neutral Organ timing. Full parent-owned body/variant/vocal suites were not repeated here.

## Bounds and audio-thread reasoning

The vocal and bowed formant-response arrays have 24 entries. Both paths use the fixed 24-harmonic generator; only Piano can expand to 42 principal modes plus six courses, and it never indexes those response arrays. `addMode` retains the fixed 48-mode ceiling.

Vocal formants have a positive 0.012 floor, so the new reciprocal response cannot divide by zero. The moving-pitch response uses a common sum-bound correction and interpolated gain targets. Material excitation normalization divides by a bound floored at `1e-12`; it neither rebuilds modes nor draws additional random values for a reference strike.

At the core boundary, parameter values are checked for finiteness and clamped before integer conversion. `compatibleVariant` accepts only the explicitly supported model/material pairs; all other pairs become Standard before variant-specific branches. Note, velocity, brightness, loss and size inputs also have local finite fallbacks. Mode anti-alias weighting still follows **host rate**, fading from 0.38 to 0.465 times that rate; it does not use the higher internal rate as a license to retain ultrasonic modes. This review does not claim the arbitrary-jump probe is a spectral alias measurement; the existing vocal suite supplies the targeted high-register spectral cutoff check.

The per-sample oscillator loop is unchanged in size and structure. New vocal formant calculations are rational resonance calculations at pitch-control updates, which occur on the existing 16-sample control schedule. They add no new per-sample transcendental operation. Existing occasional trigonometric coefficient refresh and 2,048-sample magnitude normalization remain. Articulation's exponential calculations occur at accepted note onset, while later envelope refresh/release uses captured multipliers.

`sizeof(InstrumentBody)` is **6,088 bytes** in both separately compiled baseline and revised headers on this GCC/Linux ABI; the variant integer fits existing padding. The captured `Articulation` is **12 bytes per rank**, fixed storage rather than allocation. Object sizes on other ABIs were not measured.
