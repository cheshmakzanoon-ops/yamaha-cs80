# A34 — Independent audition-verifier review

## Result

Found and corrected two related file-identity races in the new `.5` audition
verifier. Root explicitly authorized this narrow helper/test correction after
the initial read-only review. The complete offline boundary suite now passes
**12 test methods, zero failures**, in **1.738 seconds**.

**No actual `.5` audition archive was supplied, inspected or accepted by this
assignment. No native build or release qualification is claimed.**

## Finding and causal proof

The original helper calculated the expected ZIP digest from a file path, then
opened that path again for ZIP inspection. If another process replaced the
file between those operations, the recorded authenticated digest could identify
different bytes from the inspected archive. The final report also reread the
path's size instead of retaining the inspected input's length.

Similarly, `main()` checked the expected-inventory file's hash before
`source_contract()` reread that path for parsing. The earlier check therefore
did not necessarily bind the reference values actually used by the verifier.

Two focused tests reproduced these defects before changing the helper:

1. A SHA-256 finalization hook replaces a tiny ZIP containing marker A with a
   ZIP containing marker B. The test stops at preflight, before any audio or
   archive acceptance. The old helper inspected **B after validating A's
   digest**, failing the required identity assertion.
2. A source-contract loading hook replaces the reference inventory after the
   old early hash check. Prepare-only mode then wrote a contract for the changed
   inventory without raising the required hash mismatch. Its report remained
   explicitly unaccepted, but the caller's supplied reference hash was not
   honored.

Both tests failed for the intended reasons, not for fixture-format errors:
[retained pre-fix output](../verification/a34-race-before.log).

## Correction

The helper now loads a **single immutable ZIP byte snapshot**, checks its
external expected SHA-256 and optional authentic API byte count, and passes
those same bytes to `ZipFile`. The result records the snapshot's length.
Replacing or changing the pathname afterward cannot change the inspected
payload.

The expected inventory is likewise read once. Parsing, binary32 comparison,
optional Git-source-file binding and the caller-supplied hash all refer to
that same byte sequence. The hash check now compares the bytes returned by
the source-contract loader instead of an earlier read of the path.

Both snapshot reads require a regular file and are bounded: **ZIP bytes must
be below 512 MiB**, and **reference inventory bytes below 16 MiB**. The read
itself is capped, so an initially small file that grows cannot trigger an
unbounded input read. The existing expanded-archive and individual-member
limits remain unchanged. An in-memory ZIP stream can add another buffer, so
the ZIP-byte cap is not a claim that total process memory is below 512 MiB.

The existing output policy is unchanged: validation completes before a report
is created; exclusive creation refuses an existing output; an exception during
the write removes the newly created partial file. The helper does not claim
crash-durable or concurrent-reader atomic publication of the report.

## Independent contract review

Reviewed the complete verifier, its test file, the current capture producer,
and [A26's original report](a26.md). The following gates remain present after
the correction:

| Boundary | Reviewed enforcement |
|---|---|
| External artifact identity | Required lowercase SHA-256 and optional API size match the immutable ZIP snapshot. Authenticity of the supplied API evidence remains the caller's separate responsibility. |
| Source identity | Explicit full Git SHA; source tree, factory revision, producer script, writer and workflow are read from that commit. ZIP code is never executed. |
| CI identity | Supplied run and attempt are checked together; omission is explicitly reported as unchecked. Publication must supply both. |
| Complete content | Exact source-derived 171-WAV / 81-program / 40-folder roster, complete member/checksum inventory, clean/complete provenance, commands and source-generated README. |
| Inventory | All 523 ordered identities, descriptions, categories and tags, the 202 parameter IDs, and all 105,646 binary32 values match the independent reference. Optional inventory-source binding verifies exact reference bytes against Git. |
| ZIP boundaries | Canonical names, collision/type/ancestor checks, supported encryption/compression policy, bounded entries and payloads, and checksum validation; no extraction. |
| Audio and metrics | Every WAV's structure, exact frame count and settings, every finite/full-scale sample, parameter digest and all twelve recomputed measurements are checked. |
| Material coverage | All nineteen active model IDs and all five variant selections must appear among the selected program controls. This is control coverage, not an independent claim of audible dominance. |
| Qualification scope | Prepared contracts remain unaccepted; successful archive-content reports retain `release_qualified: false`. Native plugin gates and authentic producer/upload/binary bindings remain separate. |

The pinned source script is used for roster and README expectations. The WAV
measurement implementation independently recomputes the producer's reported
formulas; it checks numerical agreement, not a different perceptual quality
metric. General sound-parameter ranges, semantic tag validity and acoustic
identity belong to the bank's separate structural/rendering/review gates.
