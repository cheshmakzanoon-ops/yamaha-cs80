# A43 — Complete sequence phrases and ordinary release

## Result

The independent review passes **393 checks with zero failures** across all **27 existing sequence-category programs**: the 22 numbered original sequences, Arp Motion and four modern arps. No production correction was warranted. The probe renders the complete factory patches, including their authored bodies, oscillators, modulation and effects. It changes no preset parameter.

The review is pinned to source **6094bce18c8b19da804c2fbc9a00e31969a7f579** and a private copy of the recorded core archive. It does not anticipate the later source corrections or claim a native build result.

## Why this check adds useful coverage

A11 already established the revised dry accent contour using the real arpeggiator with a common sine carrier, mainly over the first two periods of five representative sequences. A19 established touch, echo and modulation behavior in the modern source recipes. Existing generic arpeggiator tests already cover repeated MIDI onsets, rate edits and pedal lifecycle. This review therefore checks a different integration question: whether all actual factory sequence patches retain their declared multi-note pattern and source velocities over repeated physical-slot reuse, then stop normally when the source chord is released.

## Gesture and measurement

Each performance uses **48 kHz**, 64-frame render blocks, a **12-second hold** and a **four-second release tail**. The source keys are deliberately entered out of pitch order: MIDI 55 at velocity 0.65, MIDI 48 at 0.25, then MIDI 52 at 0.95. All use MIDI channel 1. There is no reset, mute, panic, normalization, forced dry path or parameter override. Ordinary note-offs release the three source keys at twelve seconds.

Twenty-seven main renders plus four tempo controls account for **31 performances and 23,808,000 stereo frames** (496 seconds). Every sample is finite and below full scale. The highest observed peak is **−12.536048 dBFS**, in Electric Sequences 164. The last three held seconds remain audible for every program, with complete-patch RMS between **−35.086756 and −27.666646 dBFS**. These levels describe this three-key, mixed-velocity phrase, not a worst-case headroom proof.

The public Engine telemetry is read at each callback boundary. It observes exactly one held generated note at a time and no more than eight active physical voices. It records **1,697 generated onsets** and **1,689 complete gates** in the 27 main performances. Truncated gates at final key-up are excluded from gate-width measurements.

All 27 programs retain their previous arpeggiator enabled flag, rate, mode, octave span and both rank-footage settings. Every observed generated pitch belongs to the declared octave set, every generated note preserves its source key velocity and channel, and the complete ordered traces agree with ascending, descending, up/down or played-order semantics. Random programs visit multiple admitted notes without being assigned a deterministic musical order. Each main performance observes at least two sequence-lengths.

## Timing precision and host tempo

Each onset spacing and complete held gate agrees with the programmed rate and the existing **58% duty cycle**, or **45% for random mode**, within **1.333334 ms** in these observations. The callback observation resolution is 1.333333 ms; the predefined comparison tolerance is two blocks (2.666667 ms). These are held-state observations, not a sample-exact acoustic onset detector.

The arpeggiator uses the existing internal floating-point clock. The largest observed average-rate difference from the nominal setting is **0.066712%**. Consequently some phrases contain an onset shortly before the twelve-second boundary where ideal exact-period arithmetic would put it on that boundary. This is retained behavior, not a new precise-clock claim: the 6,096-byte implementation from `rememberHeldKey` through `updateArpeggiator` is byte-identical to the frozen 2026.11.4 baseline, with SHA-256 `a3ff6f2586a652f2c5cf0eaa1986e7223c48f6596def765fa3f082bf3f9d847f`.

These factory arpeggiators run at their programmed **hertz rates**, as their source documentation states. They are not host-tempo-synchronized. In the four modern arp controls, changing the reported host tempo from 60 to 180 BPM at six seconds preserves the complete observed note/gate traces, all reported energy/lifecycle measurements and the complete stereo sample digests. The probe uses FNV-1a64 for those descriptive sample digests; it does not retain or claim a separate PCM byte-for-byte comparison.

## Stopping and the audible tail

Ordinary final source-key release stops generated notes in every program: no held generated note is observed during any release-tail block. Every performance ends with **zero active voices**. The final one-second output window is at least **61.650274 dB below** the last three held seconds. Ringing and delayed bell voices retain an intentional early release tail; output need not become mathematical zero at the instant the arpeggiator stops. The recorded energy figures avoid treating existing chorus/noise floors or decaying echoes as held-note ownership.
