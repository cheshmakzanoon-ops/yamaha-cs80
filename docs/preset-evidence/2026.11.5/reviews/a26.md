## Contract and checks

The caller supplies the exact source SHA, expected inventory, external ZIP
SHA-256, and optionally the expected ZIP byte count and run/attempt. The run and
attempt must be supplied together. For native CI publication, supply both;
otherwise the report explicitly records that expected CI identity was not
checked.

The helper reads the producer script, capture writer, factory revision header
and build workflow from the specified Git commit. It derives requests from that
pinned producer script, never from code in the ZIP. It requires the reviewed
.5 totals:

| Contract | Expected value |
|---|---:|
| WAV files | 171 |
| Selected existing programs | 81 |
| Metrics folders | 40 |
| Audio duration | 1,033.2 seconds |
| Stereo frames | 49,593,600 |
| Regular archive files | 216 |
| Checksummed files | 215 |
| Inventoried programs | 523 |
| Parameters per program | 202 |
| Inventoried binary32 values | 105,646 |

All ZIP entries, including directories, pass canonical-path, case-collision,
type, ancestor-conflict, encryption, compression and size checks before file
payload inspection. The implementation never extracts the ZIP or executes
its contents. Expanded bytes are bounded below 512 MiB and individual members
below 16 MiB. The exact expected file roster and checksum membership must match;
every listed member's SHA-256 is verified.

Provenance must be complete schema 3, identify the selected commit/tree and
repository, retain both clean-source checks, contain a valid capture-executable
digest, match the exact selections and totals, and agree with the requested
run/attempt when supplied. The exact inventory and capture command arrays,
output paths and source-generated README are checked. A valid-looking manifest
does not by itself qualify the archive.

The delivered inventory must match the independent reference in all ordered
identities, names, categories, descriptions, tags and all 105,646 binary32
values. Both inventory hashes are recorded; JSON byte identity is reported
separately. An optional --inventory-source-path also requires the independent
reference bytes to equal a file in the selected source commit. Without that
option, the expected inventory remains an explicitly caller-supplied reference,
not an invented source-bound export.

Every actual WAV must have the source writer's RIFF/fmt/fact/data structure,
48 kHz stereo IEEE float32 format and exact requested frame count. Every sample
must be finite and at or below full scale. Every metrics row must retain the
ordered request, program identity, category, note, velocity, pressure, hold,
tail, complete-rank selection and exact parameter digest.

The helper independently recomputes **all twelve reported audio measurements**:
peak, complete RMS, early/body/tail RMS, peak-window time, centroid, three spectral
band fractions, first-difference tilt and stereo correlation. It uses the
captured float samples and an independent standard-library FFT. Small tolerances
cover ten-significant-digit CSV formatting and FFT rounding: 0.0001 Hz for
centroid, 0.00001 dB for level fields, and 0.0000001 for the other fields.
The delivered examples must cover all nineteen active body models and all five
variant selections, including Standard.

## Executed verification

The following command passed **10 offline unittest methods** in **1.504 seconds**:

    python3 docs/preset-evidence/2026.11.5/verification/test-audition-archive.py

The tests include:

- A mocked Git-source roster contract checking all 171 requests, 81 names,
  40 folders, 216 files and 49,593,600 frames. This is a fixture test, not a
  real-source publication claim.
- Ten inventory mutations, including a changed identity, description, tag,
  address, value, signed zero, appended ID, vector size, NaN and Boolean value.
- Duplicate/nonfinite JSON, incomplete and duplicate checksum coverage,
  sixteen malformed ZIP path/type/collision cases, and eleven malformed WAV
  format/length/frame/sample cases.
- An archive-shaped fixture with all expected filenames and matching checksums
  but intentionally invalid WAV payloads. The unchanged control reaches the WAV
  rejection; fourteen additional digest/provenance/source/run/cleanliness/
  executable-hash/selection/inventory/command/README/checksum faults are rejected
  at their corresponding earlier gates.
- Exact metrics for known synthetic stereo samples, silent samples, and refusal
  to overwrite existing evidence.

As a separate measurement check, the helper inspected five **existing baseline
WAVs**, covering Stage Keys, Aftertouch Vibrato Lead, Pressure Lead, Wind and
Marimba. Across **998,400 stereo frames**, all twelve independently recomputed
measurements matched the retained capture CSV within the stated tolerances.
The largest centroid difference was **4.805×10⁻⁸ Hz**. The retained report names
the baseline source and records each WAV hash; it explicitly reports no archive
acceptance. This validates the measurement checker, not the quality of the new
voices or any future download.

The helper's --help invocation and the scoped whitespace check also passed.

## Native artifact invocation

After the final source is committed and the actual ZIP is downloaded, invoke
with the real values supplied by the root qualification pass:

    python3 docs/preset-evidence/2026.11.5/verification/verify-audition-archive.py \
      --repo . \
      --source FULL_SOURCE_SHA \
      --run-id NATIVE_BUILD_RUN_ID \
      --attempt NATIVE_BUILD_ATTEMPT \
      --expected-inventory FINAL_INVENTORY_JSON \
      --expected-inventory-sha256 FINAL_INVENTORY_SHA256 \
      --archive ACTUAL_AUDITION_ZIP \
      --expected-zip-sha256 AUTHENTIC_API_ZIP_SHA256 \
      --expected-zip-bytes AUTHENTIC_API_ZIP_BYTES \
      --out FRESH_ACCEPTANCE_REPORT_JSON

Add --inventory-source-path if the reference inventory was retained in that
exact source commit. Use --prepare without an archive for a contract-only
report. Output paths must be fresh, and no acceptance report is written when
validation fails.

The authentic GitHub artifact/run/job/upload evidence still needs its own
verification, including original successful capture/upload steps and their
binding to the downloaded ZIP ID, bytes and digest. The capture-executable hash
is checked for presence and format here; its independent producer binding is
also outside this helper. An audition archive remains representative numerical
and content evidence, not human listening approval, acoustic equivalence or a
complete native plugin release gate.

Only this new verification helper, its focused tests, evidence and assigned
review were written. No production source, CMake, calibration, historical
evidence, commit, push or workflow change was performed.
