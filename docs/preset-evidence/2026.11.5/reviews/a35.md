## Outcome

The existing [native evidence parser](../../2026.11.4/ci/source-078c098/parse-native-evidence.py) can summarize the forthcoming 2026.11.5 JUnit, LastTest and pluginval evidence **without modifying the historical file**. Its test counts are derived from supplied evidence, and its thirteen required lane names, GUI requirements and fixed seeds match the current workflow. It has no old factory-revision, 200-control or 306-host-count acceptance constant. Its retained **523-program** expectation remains correct for this revision.

This review consumed **no new native CI artifacts** and qualifies no build. The executed diagnostic comprises **37 synthetic parser checks, zero failures**. Synthetic fixtures are clearly labeled; their passing totals are not platform test results. The parser intentionally leaves `release_qualified: false`, even when every requested observation is green.

All lanes require strictness 10, exactly 523 programs, a seed shared by console/report, the expected GUI marker, and one clean terminal SUCCESS in both copies. Console and report are two records of one invocation. The independent randomized lane is still required when its seeded regression succeeds. A diagnostic gdb or fault-trace replay cannot replace either original lane.

The parser records `validation_start_count` but does not enforce that it equals one. All thirteen retained preceding lanes had one start in each console and report. Confirm this condition on the actual new output and investigate any extra or missing start rather than inferring invocation counts solely from terminal SUCCESS.

## Linux retry scope

The unchanged wrapper allows at most three full invocations: one original and up to two retries. A retry is eligible only for shell status 139, after a started test phase ends in a completed phase, with neither SUCCESS nor FAILED in that attempt's log. That condition does not establish crash ownership or prove that the entire suite completed.

The parser checks preserved attempt numbering, maximum retry count, final original-child normal exit zero, and agreement between the number of core terminations and recorded invocations. It **does not apply the wrapper's eligibility predicate to each earlier attempt**. The probe intentionally supplied a prior `FAILED` attempt and showed that this remains an external review obligation; `retry_eligibility_requires_manual_job_log_review` was true. Inspect the actual earlier core return codes, attempt contents and original wrapper/job log before accepting a retry history.

Preserve raw negative signal return codes separately from normalized shell status 139. A normal `exit(139)` and a process terminated by SIGSEGV are different observations, although the wrapper can see the same shell status. Do not carry the preceding release's zero-retry claim into this release without inspecting the new files.

## Required external gates

1. **Source/run/attempt and authentic artifact bytes.** Bind source commit and tree, run ID, reviewed attempt, exact artifact IDs/names, byte lengths, SHA-256 digests and retention status to authentic API responses. Use original successful upload steps to bind the intended attempt. Parser input `provenance` is copied under `caller_provenance_claims_unverified`; it proves none of these claims.
2. **Six successful original jobs.** Require the four platform producer jobs and two separate Linux/Windows validator jobs to succeed. Inspect original configure/build/Test/validator/package/upload steps and unsuppressed exit handling. Evidence uploads use `always()` and therefore can exist after failure. An artifact alone does not prove a successful job.
3. **Actual test roster and skip review.** `--require-complete` requires four native and four validator targets; it does not enforce expected CTest names/counts. Require all fifteen new named tests to be present and passed on each applicable native target. Reconcile actual platform registration counts, unknowns and failures, and examine every formal skip/disabled case. Count nested unittest skips separately, never as passing CTests or additional formal skips. The old seven formal and 24 nested skip totals are historical only.
4. **JUCE provenance.** The parser includes the provenance text when present but tolerates its absence and does not validate its contents. Independently require the actual file, JUCE 8.0.11, commit `c352e2489000ffeb9e397051377d75eef2efe641`, and the original successful configured-source verification step.
5. **Validator binding and version.** Confirm actual original process exits, all thirteen required steps, retry eligibility, seeds, GUI coverage and validated paths. The parser's version text/download-JSON checks remain observations; authentic upload/source binding and the source-pinned downloader checks are still needed.
6. **Installable payload identity.** Verify each actual installation ZIP with the existing package verifier and compare complete Linux/Windows VST3 payloads to the input artifacts consumed by their validators. For Macs, bind VST3 validation paths to the unchanged packaged build outputs, and require AU source/registered-copy whole-bundle equality and matching before/after executable hashes. Architecture, formats, manifest inventories, executable headers, source/revision and checksums are separate from log parsing.
7. **Auditions and publication.** Run the new audition checker on the actual new ZIP and final inventory. Keep all historical evidence unchanged. Publish only after these gates pass; a later docs/evidence commit does not alter the qualified source bytes or justify skipping a source change.
