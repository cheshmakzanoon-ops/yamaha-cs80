No production source, workflow, shared build, Git commit or remote state was changed by this task.

## Workflow findings that shape the helper

The current `.github/workflows/build.yml` macOS job builds and tests natively on `macos-15` and `macos-15-intel`. It ad-hoc signs the source AU, copies it to the user's Components directory, requires a recursive source/copy comparison, and records both executable hashes before running four pluginval lanes. The packaging step repeats the recursive comparison and hashes before invoking the existing package helper. VST3 validation reads directly from the build product path; the macOS job does not publish a second, independent validator-input VST3 archive.

Consequently, pre/post AU hash files bind the **executable bytes**. Full installed AU resource/signature binding still requires the original successful pre/post `diff -qr` steps and exact original paths. VST3 validation-to-package identity still requires the original validated path, packaging input path, successful order and absence of intervening changes. A consistent install archive or console alone cannot replace those checks.

The package manifest contains the full source SHA, preset revision and workflow run ID but **does not record a workflow attempt**. The ordinary artifact API receipt also lacks an attempt. The helper therefore requires an explicit expected attempt and records it, but always leaves `run_attempt_bound: false` until an external original run/job check establishes it.

## Implemented checks and limits

Each downloaded ZIP is snapshotted once, hashed against its supplied API receipt and inspected from those same bytes. Bounded ZIP preflight rejects unsafe/duplicate members, unsuitable entry types, malformed directories and excessive expansion. The install ZIP must contain its expected tar archive, manifest and checksums. Exact committed source supplies the existing robust whole-inventory verifier and Mach-O header inspector; the revision declaration must agree with the requested revision.

The report includes complete AU, VST3 and Standalone inventories with canonical inventory digests, every executable digest, advertised architecture/role presence, manifest identity, packaged SOURCE/JUCE consistency, AU source/copy executable hashes before and after validation, and all four observed validator input paths. The helper does not execute downloaded binaries. It requires regular executable inventory entries for the current native layout; a future executable-symlink layout fails closed for review.

The report always leaves release qualification and validated whole-bundle identity false. Eight explicit remaining gates cover original run/attempt and upload identity, native source/tests, all four validator lanes, full installed AU comparison, VST3 path/order binding, original workflow exit propagation and other release/audio checks. API receipts remain caller-supplied records whose authenticity must come from the authenticated retrieval/original producer evidence. Expiry is recorded without claiming a download link is currently live.

## Validation

`PYTHONDONTWRITEBYTECODE=1 python docs/preset-evidence/2026.11.5/verification/a37-test-macos-binding.py` completed with **18/18 passing tests**. Fixtures cover arm64 and x86_64 success, complete resource inventory, API digest/source/run/repository rejection, wrong manifest revision/run, a missing AU resource, internally consistent wrong-CPU VST3 payload, AU pre/post/distributed hash mismatches, wrong/repeated validator paths, path traversal, duplicate JSON keys, immutable snapshot consistency, exact committed-source/revision checking, refusal to overwrite reports and explicitly unbound attempt/release status.

These fixtures are not native binaries, actual `.5` CI artifacts, listening evidence or release qualification. Their source/API/run fields are deliberately synthetic. The committed-source loader test reads the existing local Git object and verifies exact bytes; it does not execute a plugin or borrow a historical successful result.

## Handoff

After the new sound source has its actual successful native artifacts, run the documented command for each architecture with the full source SHA, run ID, expected attempt and four actual downloaded ZIP/API paths. Keep the resulting reports beside the authenticated original run/job records, timestamped logs and native parser output. Complete every listed original-job/path gate before describing distributed bytes as validated. The helper neither replaces nor edits the historical SHA/run-pinned implementation.
