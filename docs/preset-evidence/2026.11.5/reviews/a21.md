# A21 — independent host parameter and saved-state review

## Result and scope

No source-level compatibility blocker was found in the reviewed working tree.
The published **200 core controls and 306 host positions** remain a prefix of
the new **202 / 308** layout. Native APVTS, UI, AU/VST3 and pluginval execution
remain separate qualification gates; this review does not qualify a binary.

Baseline: `8685e9ed39d6347b67401da7590b7e1e8e95472d` (2026.11.4).
The review was read-only except for this report. No shared build, production
source, calibration, commit or push operation was performed.

## Host layout, state and automation findings

`PluginProcessor.cpp` changes only append the two choice parameters after the
previous layout. The existing body Model selector remains twenty choices,
0–19, so its saved normalized values retain their previous meaning. Each new
Variant selector has five choices, default Standard, and AU version hint 18;
the old model and size hints remain 16 and 17. Generic processor, library,
cached-value and snapshot arrays use `P_numParams`. `hostParameterCount` derives
from that count plus the two hardware-source and 104 memory controls.

`normaliseRestoredState` iterates every core parameter, inserts missing children
with their declared defaults, sanitizes nonfinite values, and applies the
actual JUCE parameter range's clamp/snap rule. Thus an older session or user
preset missing variants gets Standard rather than inheriting the receiving
instance's live selection. Inactive A/B restoration independently applies the
same declared defaults and parameter range. The unchanged A/B save and restore
loops include all `P_numParams` entries. MIDI learn stores host parameter
indexes and bounds reads by the actual parameter array; old indexes do not move.

Variant values are decoded into rank settings and passed to the body only at
accepted note onset. The material header makes incompatible model/variant pairs
use Standard. This fallback does not rewrite the saved selector. The actual
host regression exercises both ranks and all four nonstandard variants: a
live edit must leave the sounding body bit-identical, and the next accepted
note must produce an audible difference. That is stronger than a metadata-only
round-trip test.

## Test and UI coverage reviewed

The extended `InstrumentBodyHostTests.h` checks the independently frozen
200-core and 306-host prefix hashes, old definition fingerprints, exact choice
labels, all normalized variant positions, session/user-preset/A/B recall,
malformed-state rounding and bounds, missing-field defaults, undo/redo, all
523 factory and MIDI program recalls, and next-note audio behavior.
It is invoked both by the full UI smoke and by the registered
`cs80_modern_recall_host_tests` entry point. Native execution remains pending
at this review.

`TypedValueUnitTests.h` directly includes the body header that supplies variant
names. The existing parser's integral-range path handles the new 0–4 choices:
exact names and unique case-insensitive prefixes succeed; ambiguous `Choir`,
single-letter `S`, numeric `3`, malformed suffixes and `NaN` reject without
changing the output value. Both variant IDs were added to the UI snapshot and
library-audit discrete classifiers. The production formatter supplies the
same five names as the host choices.

## Bounded stale-count scan

Commands inspected included:

```sh
git diff 8685e9ed39d6347b67401da7590b7e1e8e95472d -- src/core/Params.h src/plugin/PluginProcessor.cpp src/plugin/UiComponents.cpp tests/ParameterStateChildIndexTests.cpp tests/TypedValueUnitTests.h
rg -n '\b(200|306)\b' src tests scripts -g '*.{h,cpp,py}'
rg -n 'P_body1Model|P_body2Model' src tests -g '*.{cpp,h}'
rg -n 'P_numParams|hostParameterCount' src/plugin
```

No stale production parameter-array bound of 200 or 306 was found. Remaining
references in the reviewed parameter tests intentionally assert the published
prefix. Other numeric hits are timing, frequency, geometry or unrelated test
fixtures. `scripts/compare-preset-audio.py` and
`scripts/compare-preset-refinement.py` retain their historical 2026.11.4 / 200
contracts; they must not be presented as 2026.11.5 acceptance. The new
`compare-preset-response.py` explicitly checks the 200-to-202 transition.
