# A22 — Independent bank identity and structural coverage review

No blocking identity, address, or structural-coverage defect was found in the
reviewed development snapshot. An independent binary32 comparison confirms
**523 preserved ordered identities, 521 changed musical programs, two unchanged
initialization programs, and no duplicate non-volume control vectors**.

This is an independent data and address review. It does not establish sound
quality, acoustic equivalence, audio safety, native-host behavior, or the
provenance of a final downloadable binary. Root was still calibrating the bank
while this review ran; the final coverage report must be regenerated from the
final inventory after calibration.

## Independent comparison

A separate Python comparison used `struct.pack('<f', value)` and did not call
the new comparator's `compare()` implementation. It checked the complete
ordered tuples `(index, host_index, name, category)`, the 200-ID prefix, and all
old/new control values at engine precision.

Both Init Patch at host 43 and Init Circuit at host 522 preserve every original
metadata field, all 200 old control values including master volume, and have
zero for both appended variants. Every other program has at least one changed
old control after excluding `volume`, `parity_mode` and `source_performance`.
The changed-old-control count ranges from **1 to 54**, with **median 6**.

The two programs with one changed old control are **Pressure Keys** and **Sub
Bass**. Each changes `ch1_v_level`, the fixed VCA contribution on its active
main rank. These are actual playing-response controls, rather than a master
output trim or metadata edit. Their detailed behavior belongs to the keyboard
and bass render suites.

An additional route check found an amplitude-envelope or touch change on at
least one enabled source rank in **all 521** musical programs. For each rank,
that check required positive rank mix, a positive sum of fixed/initial/pressure
VCA contributions, and an active body, bypass sine, or oscillator/noise source
with positive VCF level. It then required a changed attack, decay, sustain,
release, fixed VCA, initial-level, or pressure-level control on that rank.
There were **zero exceptions**. This establishes an eligible audible route;
rendered behavior remains a separate requirement.

## MIDI and host address proof

A private C++ diagnostic included `core/FactoryPresets.h` and compiled
`FactoryPresets.cpp` directly, without altering the shared build directory.
The same diagnostic was then built with the frozen baseline's headers and
FactoryPresets source, keeping the 200- and 202-parameter layouts separate.

Each binary checked:

- Exactly 222 original and 301 curated entries, concatenated in the existing
  order to form 523 host programs.
- Every host program's name and category against its respective bank entry.
- Every host-to-curated index conversion, including original-bank rejection.
- All **128 × 128 × 128** valid MIDI bank-MSB, bank-LSB and Program Change
  tuples. MSB 0 maps curated offset `LSB * 128 + program` to host offset 222;
  MSB 1 maps original offsets directly; unused addresses and all other banks
  return −1.
- Negative/out-of-range LSB and program values, and boundary conversion cases.

Both independently compiled binaries produced the same result:

```text
Address check: 2098771 checks, 0 failures; ordered identity FNV64=36e918f3a865648c
```

The identity digest encodes each decimal host index, name and category as UTF-8
bytes with a zero separator after each field, using FNV-1a-64. Source inspection
also confirms that `programLibrary`, `programIndexForCurated`,
`curatedIndexForProgram`, and `programIndexForMidi` are unchanged from the
baseline. The FactoryPresets changes are the new variant include and resetting
the selected rank's variant when applying a hardware tone; the header's sound
revision changes to 2026.11.5.

## Comparator review and negative controls

`python3 scripts/compare-preset-response.py --self-test` passes its two valid
fixtures and 16 rejected mutations. Inspection confirms that the production
CLI, rather than only the internal comparison function, checks the exact
baseline inventory bytes and both required revision strings. It binds both
input hashes in the report, rejects duplicate JSON keys and nonfinite numbers,
compares values as binary32, rejects master-only and variant-only coverage,
preserves the complete old ID prefix, and writes the result atomically only
after all comparisons pass.

Fourteen additional CLI negative controls were run against copies of the actual
inventories. Every invocation failed, and every invocation left a pre-existing
sentinel output report unchanged:

1. A missing program.
2. A boolean host index.
3. A moved inventory index.
4. The wrong candidate library revision.
5. A nonstandard factory variant with zero body mix.
6. A boolean parameter value.
7. A finite JSON number overflowing binary32.
8. An actual program restored to its old non-volume vector.
9. That unchanged program with a different master volume.
10. A nonzero appended variant in an Init program.
11. Two identical sound vectors with deliberately different master volumes.
12. A duplicated JSON `schema` key.
13. A JSON NaN constant.
14. A semantically identical baseline serialized with different bytes.

The last case was rejected by the frozen SHA-256 binding; the report was not
rewritten. Private fixtures and diagnostic executables were held under
`/tmp/cs80-a22` and are reproducible development aids, not release evidence.

## Limits and required integration gates

The comparator deliberately does not validate all ranges or the meaning of
all existing non-body controls, prove tag vocabulary/modern-tag consistency,
or decide whether a particular parameter edit is perceptually significant.
Those are separate bank-audit and rendered-behavior gates. It also does not
authenticate its caller-provided source label or bind the capture executable;
the report explicitly states that limitation. The final audition provenance
and native bundle qualification must supply those bindings.

No production source changes, shared-build changes, commits or pushes were made by A22.
The final recommendation is to retain the comparator as a structural gate,
regenerate it after final calibration, and publish its result alongside the
separate render, native-host and archive qualification evidence.
