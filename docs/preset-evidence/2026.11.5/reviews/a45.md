# A45 — Factory reload and saved-session user path

## Outcome and scope

The source provides a direct way to load the revised existing factory recipe:
**Library → FACTORY LIBRARY → select the entry → LOAD (or RELOAD)**. No recall-code
correction is required. The installation and preset guides explain this route,
saved controls, same-name user patches, REVERT and fresh notes. A follow-up
packaging review found and corrected two stale current-revision labels in the
installation guide; the button wording now explicitly allows either label.
The proposed final-use wording below also clarifies the note-on boundary.

source/document/inventory files and recorded 17 source-backed observations.
Those are **not executed UI or native test counts**. A45 performed no DAW

## What the actions actually do

| User situation or action | Source behavior | Practical instruction |
|---|---|---|
| A genuinely fresh processor instance | The constructor applies curated entry 0, **Brass Swell I**, at host index **222**. A host can subsequently restore a saved state over it. | A new default instance is a useful comparison point; reopening an old project is a different operation. |
| Reopen a saved DAW project | `setStateInformation` normalizes and restores serialized controls, then restores the name/index and A/B state. It does not call `loadFactoryPreset` to replace saved controls with current catalogue values. | The familiar name alone does not prove the revised recipe is active. |
| Press LOAD or RELOAD | The browser calls `loadSelected → loadEntry → loadFactoryPreset`. That path has no “already this index” early return. | Explicit loading works even when the desired factory name is already displayed. |
| Press Enter in the result list or search field; double-click a result | These callbacks reach `loadSelected`; search Enter first applies the pending search. | These are alternatives to the explicit button within the Library. |
| Select, search, sort or reopen the Library | Selection and sound loading are separate. Search/filter/restore selection never auditions by itself. | Highlighting a result is not sufficient proof that it was loaded. |
| Audition is on and a known loaded row is clicked again | The `isLoaded` guard preserves the sounding patch and its edits. | Use the explicit button to replace the edited/current recipe. |
| A project restores a factory-like name | Runtime origin is deliberately **unknown** after path-free serialized recall. The browser does not infer identity from a display-name match. | The button can correctly say **LOAD**, rather than RELOAD; either explicit action is appropriate. |
| A saved user patch has the same factory name | Runtime file provenance remains separate from a factory address. `FACTORY LIBRARY` shows the factory entries. | Choose that scope when requesting the current factory recipe. |
| Choose REVERT | The browser restores the captured opening sound, including its sound controls, sources, memories and modern configuration. | REVERT may restore the older recipe; it does not mean “load the newest factory values.” |
| Toggle A/B | The destination recalls its stored snapshot. Serialized inactive slots are completed from defaults independently of the receiving live values. | A/B can return to old/custom settings after a factory load. It is not another factory reload command. |

The catalogue remains **523 entries**, with original addresses 0–221 and the
later collection at 222–522. Init Patch remains at 43 and Init Circuit at 522.
No entries are added by this review.

## Factory loading reaches the new bodies

`loadFactoryPreset` calls `applyValues` with its default `resetSources=true`.
Both hardware-source selectors are therefore set to **PANEL** before the
factory sound controls are published. A previous hardware-tone or MEMORY
selection cannot silently keep the revised factory instrument body masked.
All twelve body controls are sound parameters, so they are included in this
recall. No manual material/vowel setup is required to play the factory recipe.

The same operation deliberately retains physical setup and session controls:
controller curves, KAS scan timing, ribbon CC setup, tuning source, pedal/jack
configuration, listening output, oversampling and unit-condition selection.
It also retains held-note/controller ownership and active host automation.
Factory loading is consequently not a reset of every session state or every
existing DSP history. An isolated comparison should use fresh notes and allow
previous held notes/pedal tails to release; host automation can still make its
own subsequent writes.

At accepted note onset, `Engine::startVoice` captures the body model, partial
decay, resonant size, variant and articulation profile. Body mix and brightness
remain live. A held note is not rebuilt merely because a selector changes.
The GUI publishes parameters for the next audio block; it does not reconstruct
voices on the message thread. This is why the guides' “play fresh notes” step
matters even after the correct factory row was explicitly loaded.

## Older body data and A/B snapshots

| Incoming stored body data | Restored body values |
|---|---|
| No body fields | Models and mixes default to 0; brightness to 0.5; partial decay to 1; sizes to 1; variants to Standard (0). |
| Original eight body controls but no geometry/variant fields | The eight present controls are retained; both sizes default to 1 and both variants to Standard. |
| Preceding ten-control, size-aware patch | Those ten fields are retained; only the absent variants default to Standard. |
| Current twelve-control patch | All twelve stored controls are restored, subject to the declared finite/range/choice validation. |

Session and user-file restoration both use `normaliseRestoredState`. Inactive
A/B slots independently read each field with `paramDef(i).def` and the declared
host range. Missing fields therefore do not inherit the receiving instance's
currently selected body or nonstandard variant. Retaining old values is
intentional compatibility behavior, distinct from selecting a new factory
recipe. The earlier A21 numerical ABI work is not repeated here.

## Retained Studio routing does not leave a hidden factory modulation route

A focused source/data inspection addressed one additional possible stale-state
path. Factory loading publishes parameter values but does not erase the stored
MSEG shapes or matrix-routing configuration. However, the exact committed
523-program inventory contains **zero in all 16 matrix-amount parameters for
every program: 8,368 values inspected, no nonzero value**. These amount fields
are recalled sound controls. `ModernLayer::rebuild` excludes a slot whenever
its amount is zero, so a retained route or MSEG shape cannot contribute through
that matrix after the factory values take effect. Subsequent user or host
writes remain separate behavior.

This is a source-and-inventory conclusion, not a new runtime or audio test.

## Suggested final-use wording

After installing the updated build and rescanning or reopening your host, open
**Library → FACTORY LIBRARY**, select the factory entry, and press **LOAD** (or
**RELOAD**, if that is the label shown). Do this even if the same preset name is
already displayed. Let held notes and the sustain pedal release, then play
fresh notes; the body model, decay, size and variant are captured at note onset.
Save the project to keep the revised settings. Older projects, saved user
patches and A/B slots retain their stored controls. **REVERT** restores the sound
present when Library opened, which may be the older recipe.
