# Ordinary Program Change updates the active extension

## Intentional sound correction

The ordinary MIDI Program Change path previously published its recalled control frame only to the primary instrument. An already-active sixteen-voice extension could keep its previous patch/policy for the rest of the callback. The supported VST3-curve path already published to both active instruments.

This correction extends control-frame publication to an already-active extension after a valid ordinary program recall. A policy change restores its existing physical expression target just as the established VST3-curve path does. It does not activate an inactive extension, retire an active one earlier, change note routing or change the existing block-boundary voice-mode policy. The VST3-curve path remains unchanged. Invalid/rejected programs and eight-voice operation retain their previous paths.

This is an intentional audible correction, not a bit-identical optimization. The earlier [host automation](HOST_AUTOMATION.md) work preserved ordinary recall as its integration boundary; this follow-up explicitly supersedes that narrow requirement. Historical 336-case baseline compatibility captures are not claimed for the newly corrected active-extension program cases. Frozen old contracts and acceptance tolerances remain intact rather than being silently weakened.
