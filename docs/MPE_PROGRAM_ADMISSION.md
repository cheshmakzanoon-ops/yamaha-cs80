# Role-aware native MIDI program admission

The native library adapter previously assumed that channel 1 was always the MPE manager. This rejected program selection from an active upper-zone manager on channel 16, while allowing channel 1 to select a program even when it was an upper-zone member.

MPE v1.1 section 2.3.3 requires a Mode-3 receiver to ignore Program Change on member channels. Table 7 describes manager-channel program selection. The official source is identified in [MCM defaults](MPE_CONFIGURATION_BEND_DEFAULTS.md). Bank Select is different: Table 5 permits optional member-channel reception. Keeping its admission aligned with Program Change is this instrument's existing shared-bank product policy, not a claim that the specification prohibits every member bank byte.

The adapter now shares one admission predicate for Bank Select and Program Change. PURE continues to reject both. With effective MPE disabled, existing all-channel acceptance remains. With MPE enabled, current lower and upper managers are accepted; channel 1 with no assigned role retains its conventional compatibility fallback. Members and other unassigned channels are rejected. Roles are read at event dispatch, including after a preceding same-offset MCM.

The instrument still has one shared bank pair and one global program. This is not independent per-zone multitimbrality. Recall remains unchanged: it can replace MPE and voice-mode parameter values, and later events follow that new effective state. The existing distinction between ordinary and VST3-curve recall/extension synchronization is not expanded into a new simultaneous two-engine recall guarantee.

## Evidence

On source `120c7af5`, the native fixture ran 5,248 checks with 600 failures confined to negotiated upper-manager, reversed channel-1 membership, shared-bank and event-order admission. All conventional/PURE and unchanged routing controls passed. The same fixture passed 5,248 checks with zero failures after the predicate correction (registered CTest: 6.52 seconds). The initial fixture build needed an enum initializer-list type correction before the baseline could run; that build failure is retained separately. The affected native build completed 15 steps. The selected integration passed 33/33 tests in 126.16 seconds, including all six VST3 rate/mode configurations and the direct-processor multi-recall state witness. Independent source/test review found no blockers. A separate completed repeat passed the same 33/33 tests in 126.71 seconds, with 5,248/0 program-admission checks, 65/0 direct-processor multi-recall checks and 204/0 allocation checks. The native fixture observes actual program indices, recalled parameter values and preserved state on rejection, including lower/upper/reversed endpoint roles, bank poisoning, shared bank usage, same-offset changes, PURE and conventional controls. The fixture configures Legacy/Circuit and eight/sixteen-voice modes with zero/rendered blocks, but does not allocate sounding voices; it checks program indices and parameter publication rather than audible extension recall. This is direct processor qualification, not external DAW/controller or CPU/deadline qualification.
