# Prospective host/execution contract

`host_contract.py` freezes the exact 12 original Sub/Ring CTest command vectors, timeouts and output names. These vectors were independently compared with actual configuration-preflight CTestTestfile.cmake definitions. All six rate/mode cases per fixture stay enabled. The default Sub case uses its original five arguments; Ring never receives --compat-only. Numeric capture names follow the actual fixture source, not descriptive labels: e.g. `8-13-20-noqueue.pcm`, `old20-4096.pcm`, `28-8-13-policy2.pcm`. All462 files must exist at32768 bytes each, without extras/symlinks, and match across arms. This does not claim exact active-automation output for paths whose original fixtures only assert invariance/effects.

The full release guard requires the same569 unique tests/properties, no disabled tests and an executable command for every test after full build. Because prebuild CTest JSON omits509 unresolved command vectors, the orchestrator MUST additionally preserve raw configured CTestTestfile.cmake texts/hashes and use verify_definitions after all configurations AND after selected/full builds. Missing-command slots are not permission to substitute different test commands. Preserve the final resolved JSON roster and full raw definitions as evidence.

No held-out test runs before the sole profile is frozen. Both complete immutable arms must be sealed before qualification. To preserve original host argv, restore the sealed baseline VST3 bundle (including moduleinfo) to the canonical build path and hash-check before/after every original host invocation; then restore/hash-check the sealed candidate bundle. Restore files only, never rebuild between arms. Candidate remains canonical thereafter. Additional release test targets may be linked only against the unchanged frozen candidate archive; any Engine/archive/module/Standalone/benchmark byte change invalidates the experiment.

`execution.py` supplies a persisted single-attempt command ledger,300-minute hard total deadline and90-minute informational compatibility progress milestone, per-command limits and benchmark affinity witnesses. A failed or timed-out command latches terminal failure, including against differently labeled retries or phase advance. Timeouts kill the newly created subprocess group, including compiler/test descendants. The90-minute milestone only records delayed compatibility progress, never aborts or grants a pass. A later release-stage switch cannot rescue an expired global deadline. These helpers do not dispatch a workflow or run project workloads by themselves.
