# Native actual-byte identity prerequisite (preparation only)

`native_identity.hpp` is Linux/POSIX C++17 code with OpenSSL EVP SHA256. It does not load a module, create a synth, expose a production CLI, or launch qualification. Thirty-six tiny inert-file tests compile one fixture against the installed system libcrypto. Python independently creates expected file SHA256 values and verifies both canonical expected-manifest and verified-evidence digest encodings.

## API and semantics

`cs80_identity::VerifiedIdentity::verify(const ExpectedIdentity&, Caps)` validates all expected schema/bounds, takes an owned deep copy, walks/reads actual files, compares every observed record, and only then returns `shared_ptr<const VerifiedIdentity>`. Constructors are private; copy/assignment are deleted. No caller hash string alone creates a verified object. The immutable snapshot includes caps, arm, canonical bundle/module path, complete bundle entries, root owner/mode, and exact named runtime/input file records. There are no caller references or mutable freshness flags. `reverify()` returns new evidence only after rescanning the stored frozen expectations and comparing complete evidence (including observed device/inode identities), or throws. Old objects remain historical evidence, NOT proof of present freshness. The owner must invoke reverify immediately before load and again after unload.

The expected bundle includes exactly one root directory record and exactly one designated regular module path; it may contain other regular libraries/resources. Its entire file/directory inventory, modes, owners, sizes, and content hashes must match. Runtime/input scopes are deliberately different: sorted, distinct, disjoint canonical root paths plus explicitly enumerated files only, not recursive inventory of `/usr/lib`. Each root must be used. Bundle/runtime roots must be mutually nonoverlapping; duplicate file records, hardlinked files, duplicate observed device/inode nodes, symlinks (including ancestors), special nodes and special permission bits are rejected. Every root is anchored through an `openat` O_NOFOLLOW directory walk starting at `/`; file and directory traversal is fd-relative. No writes are performed by the verifier.

Caps explicitly bound total bundle-entry + input-file count, regular-file count, logical bytes hashed, and path byte lengths. Input-root count has the entry cap separately; intermediate runtime ancestor directories are bounded by the path cap, not claimed as inventoried runtime entries. Supported envelope: at most 1,000,000 entries and 4096 path bytes. Checked subtraction/addition prevents byte/count overflow; unexpected directory names are bounded before vector growth, file size admission precedes reading, actual read growth beyond admitted size fails, and pre/post fstat (including nanosecond mtime/ctime) rejects ordinary in-read mutations. The fixture injects truncation/growth of the actual currently read module file and a failing EVP update. EVP allocation/init/update/final all fail closed in code; only update failure is injected by this fixture.

Accessors: `arm()`, `modulePath()`, `expectedManifestDigest()`, `evidenceDigest()`, `expectedEncoding()`, `evidenceEncoding()`, `sameEvidence(other)`. Equality compares complete canonical evidence, not only hashes. Encodings are version-tagged, length-delimited, unsigned little-endian 64-bit fields, with exact byte strings. Canonical manifest input order is validated (bundle root first then remaining paths, runtime root paths, input labels sorted). Expected-manifest digest is separate from verified-evidence digest; latter includes the former's FULL encoding plus actual device/inode records in deterministic bundle depth-first/runtime-root order. Root directory size is canonical zero, not a filesystem-specific st_size; timestamps are mutation checks, not frozen identity fields.

## Mandatory adjoining gates and nonclaims

- Expected inventory authenticity and completeness are independently trusted adjoining gates. Hashing a manifest does not establish its authority. Equality cannot detect omitted entire runtime/input files or a dishonest expected bundle. No self-generated manifest may stand in for independently frozen inputs.
- Private bundle/source trees must be owned/quiescent; trusted runtime roots may be root-owned OS trees. Numeric expected/observed uid/gid/mode equality is recorded, but the verifier does NOT infer that those owners/permissions are trusted or that no concurrent writer exists. Orchestration must establish this. This is not an adversarial race sandbox.
- Follow-on module owner must bind an actual retained/opened file handle/inode and symbol-provider/link-map evidence to this verified identity. Merely reopening `modulePath()` after hashing is NOT loaded-image proof. The base identity object cannot alone enable a reload-transfer token. The separately tested `native_identity_pin.hpp` extension retains a verified file descriptor; it still does not prove that a dynamic loader used it. See its status file.
- Full dependency/environment closure and actual runtime loaded-image/provider identity are not discovered. OpenSSL config/providers, dynamic linker, libcrypto, helper source/binary, compiler/toolchain and runtime dependencies must be independently frozen and authenticated before qualification. Current inert tests use system OpenSSL; they do NOT establish a qualification runtime provenance seal.
- Original release/host/test gates, production archive/map/ELF binding, lifecycle/state/CID/policy/history proofs remain unchanged and required. The object proves observed files at checks, not processing equivalence, timing, factory class identity or complete lifecycle.
- On verification/reverification failure, orchestration must latch terminal failure. No retry/session admission policy is implemented here.
