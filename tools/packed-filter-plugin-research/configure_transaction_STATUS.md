# Bootstrap-to-baseline-to-overlay configuration transaction (preparation only)

`configure_arm(contract, Commands)` now executes the concrete prerequisite for the existing build transaction rather than trusting an arbitrary preconfigured directory. No CLI, workflow or real qualification launch is exposed. The public entry is admitted only once before the stock build, requires the full normal 587 compile records and 569 tests and fixed production final paths, and rejects a candidate-labelled reconfiguration. The same frozen warm-overlay common contract is then reused by both build arms; it does not reset/reconfigure the stock build tree between arms. Only the private reduced-count entry is exercised by tiny inert fixtures.

## Transaction and downstream payload

- Starts at an unconfigured canonical build path: absent/empty, or exactly the independently frozen dependency seed file/directory inventory. Existing CMakeCache/build.ninja/compile database is rejected. Source, build, retained evidence and Commands logs are disjoint. It does not tear down a built stock arm or delete previous build outputs. One admitted common configuration can feed the normal stock build and later candidate-only rebuild at the same paths.
- Runs the exact normal Linux configure flags from `configure_preflight.configure_argv`: Ninja, Release, plugin ON, tests ON. The executable is the absolute frozen CMake. Three explicitly planned single-attempt stages: cold bootstrap normal configure, warm normal baseline configure, then overlay reconfigure, all at identical source/build/environment paths. Each has a unique ledger label and is charged to the same deadline/budget. No failed stage triggers a fallback or retry. Only the overlay stage adds the exact absolute `CMAKE_PROJECT_TOP_LEVEL_INCLUDES` overlay argument.
- Uses the existing single global Commands deadline/terminal ledger, exact replacement environment and empty owned-process-group requirement. Verifies actual argv, cwd, exit, environment digest and group status. Audits declared source/helper/tool/dependency bytes and the complete bounded nonsymlink/nonhardlinked/no-special-node build tree around every process. All exceptions persist terminal failure; no retry is admitted.
- Supports two explicit provenance modes. Independently-expected mode matches supplied generated hashes/command rosters. Authenticated-generation mode instead requires independently declared generated/definition scopes with null expected hashes and observes newly generated bytes from the frozen source/helper/tool/config/environment/seed transaction. It does not pretend probe binaries or generated hashes were preauthorized. Both modes freeze bootstrap evidence and the warm baseline for exact overlay comparison; complete expected test names remain independently frozen. Before each actual CTest show-only invocation, rechecks generated bytes, literal definition grammar, CTest runtime identity, hooks/control-file absence and inherited CTEST_* restrictions. CTest names must match the independent complete expected list. Warm baseline and overlay CTest documents/definition bytes/compile bytes remain identical; parsed cache differs only by the exact overlay variable. Raw Ninja graph text may change only by the two exact map options and two literal overlay regeneration-input references. Graph inspection currently supports unescaped canonical build/overlay paths only; whitespace/$/#/: paths fail closed rather than being normalized. Full warm/overlay inventories and modes must match; only CMakeCache.txt, build.ninja and the explicitly diagnostic Testing/Temporary/LastTest.log may differ in bytes. Cold-to-warm bootstrap changes are preserved as setup evidence, not attributed to the overlay.
- Actual Ninja `-t commands` outputs are compared in order. Exactly the two final link commands gain one exact map/cref option each; removing that one option reproduces each baseline argv. Every other command remains byte-identical. Opaque response-file tokens are rejected rather than expanded heuristically. No project compile, link or test command is invoked by this transaction.
- Retains the ENTIRE bootstrap and warm baseline generated trees (including compiler/configure diagnostics) before their next planned configure can overwrite them, then the entire overlay tree. Copies/hashes in 1 MiB chunks with deadline checks; validates original size/inode/mtime/ctime/mode, copied hash and equivalent complete inventory, preserves file/directory permission modes, and rechecks all three retained snapshots at final admission. Original build files are not deleted. All actual execution logs remain in the Commands directory and their hashes are rechecked. Snapshot identity does not assert output ownership/ACL/xattr equivalence.
- Captures exact CMakeCache/toolchain generated files and declared dependencies/generated-input scopes for downstream `input_manifests`, actual compile database, actual Ninja roster, canonical ar/CMake/Ninja paths, final outputs and build-tree cap. Cache tool spellings and their canonical resolved runtime file identities are independently frozen separately, accommodating ordinary OS compiler/ar symlinks without trusting a new resolution. Helpers have an independently expected implementation hash scope. `common_contract_sha256` binds the complete returned common configuration payload; the caller must preserve/bind this receipt when constructing `build_arm` input. This does not itself run that build.

Environment values are not serialized as an environment dictionary; only its digest enters the common receipt and command ledger. Raw configure/cache/log evidence is intentionally preserved, not redacted, and may naturally contain compiler configuration derived from the environment. The prospective runner must use an independently frozen non-sensitive environment and never include credentials in flags or diagnostic output.

## Inert evidence and limits

37 actual tiny configure/inspection controls pass (explicit CMake 3.31.6 and existing Ninja paths). Independent fixture setup configures its own temporary inert project to freeze expected bytes, removes only that fixture-owned setup directory, then tests the transaction. It is a test oracle, NOT provenance for real CS80 manifests. Controls cover complete three-stage success, seed/dependency identity, runtime alias/helper drift, generated/compile/test/Ninja mismatches, hooks blocked before show-only, symlink/hardlink/size/count gates, deadlines, ledger environment corruption, terminal retry rejection, and retained baseline/log mutation. CMake compiler capability probes run during configuration. A real JUCE configure may build/run its configure-time setup helper. This is NOT a claim of no code execution; no synth/project target is built or executed by these fixtures or the transaction's direct commands.

Bounds: each complete tree is at most the contract's entry/byte caps (hard envelope 250,000 entries and 16 GiB); metadata read into memory has a separate 64 MiB ceiling per file. A separate cumulative retained-entry/byte budget includes ALL three snapshots, existing command logs, and the final streamed receipt. Each snapshot is reserved before copying; actual usage is rechecked around every completed command and at final admission. Receipt serialization is streamed and capped at 64 MiB. Commands child-output growth while a process is still running is not intercepted by this wrapper; exceeding the cumulative budget is terminal when the command returns. A hard runtime storage/logging quota is therefore still a prerequisite before a real launch, not established by post-command admission checks.

Expected manifests and their scoped inventories must be authenticated and complete independently. Equality cannot detect identical omissions in expected source/runtime/dependency/generated scopes. This code does not discover complete CMake module/toolchain/sysroot/dynamic-library/provider closure, nor authenticate a self-supplied manifest. Required implementation files are a minimum, not a claim to discover the entire Python runtime/import closure. Raw complete generated-tree retention is evidence, not automatic authorization to trust every generated file. Subsequent build/seal/map/object/native-loader/lifecycle/compatibility/timing gates and cross-arm filter-only source change validation remain mandatory. No production qualification follows from this receipt.

The receipt lists retained-equivalent CTest diagnostics (original path, retained path, exact hash and mode) for the overall coordinator to verify again before retiring them ahead of the suite. This transaction does not delete them silently; the suite’s fresh-log gates remain unchanged.
