# Retained verified-module descriptor (preparation only)

This extension adds typed `ModuleStamp` and `PinnedModule`. Seventeen tiny inert-file controls plus the existing 36 identity controls pass. No module is loaded, and no qualification CLI/workflow is provided.

`VerifiedIdentity::moduleStamp()` returns a const reference to device/inode/size/mode/uid/gid/SHA256 captured from the SAME designated-module read that admitted the complete immutable identity. The stamp is not obtained by a later pathname stat. All stamp fields are already included in the previous versioned evidence encoding (device/inode in observed records; size/mode/uid/gid/hash in the exactly matched manifest). Encoding version and digest behavior are unchanged; independent Python golden checks still pass, and an added independent stamp check compares every field to Python stat/hash records.

`PinnedModule::pin(shared_ptr<const VerifiedIdentity>)` first fully reverifies stored expectations, then opens the exact designated module under a no-follow anchored bundle root/intermediate-directory walk. It verifies the opened descriptor is read-only and a regular, single-link file; fstat metadata and EVP-hashed actual bytes must match every original stamp field. It fully reverifies all paths again, then rechecks the retained descriptor again before returning a private-constructor immutable capability. RAII owns the descriptor on all exception paths; copying/moving is disabled. This capability owns shared immutable identity, so caller identity lifetime ending is safe.

Accessors: `identity()` returns const shared identity reference, `stamp()` const stamp reference, `borrowedFd()` borrowed integer descriptor. The caller MUST NOT close/reassign/dup2 the borrowed descriptor or use it after capability destruction. The capability is a disciplined in-process API, not a security boundary against malicious code inside the same process. `recheckHeld()` uses pread (does not change shared file position), fstat before/after, bounded size, and EVP hash to revalidate the held inode against the original stamp. A stale pathname check cannot substitute for this operation. The normal-path loader must retain the capability through load AND unload, invoke held checks at its reviewed boundaries, and also use identity path reverify where required.

Tests cover same-bytes/new-inode pathname replacement, same-size changed content, symlink/intermediate replacement, a mutation triggered during pinned-descriptor hashing that causes the SECOND full reverify to fail, held content/mode/growth/truncation/unlink/writable-descriptor substitution, EVP failures, caller lifetime, offset preservation, and /proc/self/fd descriptor counts on success/failure. Test interposition only mutates tiny inert files; production helper has no test hook. Descriptor counts test exercised failure paths, not every conceivable allocator/OS failure.

Retaining the FD does NOT prove that normal-path dlopen used those bytes. This does not grant loaded-image/provider authority or enable transfer-token minting. Loader integration must reject stale preexisting target mappings and prove actual link-map/export providers and file-backed ELF mapping identities/offsets against the retained file, plus preserve the complete ownership/lifecycle gates. Expected manifest authority, runtime closure/provider identity, compiler/helper/OpenSSL provenance, quiescent trusted roots and external terminal-failure latch remain mandatory as documented in native_identity_STATUS.md.
