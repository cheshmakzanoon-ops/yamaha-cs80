# Process-lifetime supervisor: preparation only

The supervisor binds one explicit stock or candidate A-D child invocation to a
fresh 256-bit nonce, actual PID, exact command/environment, successful exit and
owned-process-group completion. It verifies the frozen driver, helper, request,
module and declared input/runtime files before and after execution. An exclusive
fresh output directory must contain exactly one owned, single-link, mode-0600
framed receipt. The complete canonical A-D payload is retained and the receipt
is re-read after validation. Any error is terminal; a plausible receipt cannot
override a nonzero child exit, deadline or surviving process-group member.

The decoder independently checks framing, hashes, schemas, case/CIDs, three
protocol hashes, state policy and restored bytes, six-task ordering, worker totals,
provider maps/objects/export offsets, thread identities and module teardown ledger.
It deliberately does not independently reproduce every inner native metadata,
PCM or protocol semantic check: the exact frozen native private producer remains
a trust prerequisite. Public execution requires a native driver; the script seam
is private and used only for deliberate receipt mutations.

Tests cover synthetic receipt/ledger mutations and actual terminal native inert
children, including ordinary unload, explicit NODELETE, genuine GNU_UNIQUE,
failed ModuleExit and a full plausible receipt followed by output-close failure.
Expected native identity and workload protocols are computed by a separate
file-verification/pure-encoding probe before launching the child, never copied
from the receipt being tested. This probe and the legacy native fixture are test
code, not the standalone production request parser.

The public argv is fixed to driver, request path, exact request SHA256, nonce and
receipt destination. Arbitrary fixture modes are private test seams. Receipt
opening is nonblocking and rejects non-regular objects after opening; a FIFO
regression test has an independent outer watchdog so a future blocking-open bug
cannot stall the test process indefinitely. Full canonical case identities include
the control/event roster and have an explicit 1MiB cap, not a small case-name cap.

The execution model requires trusted, owned, quiescent roots, non-escaping child
process groups and complete externally selected runtime/input closure. File hashes
and a nonce are not a hostile-code sandbox or independent attestation. The separate driver suite joins this public supervisor to the standalone native
request parser/driver for one inert workload. Runtime closure discovery, authentic
production requests/provenance, UI interoperability, full real-plugin grid and
release qualification remain separate gates. A retained
provider is reported as retained; process exit is never called physical dlclose
unload. No E-transfer authority, CPU timing or production qualification is granted.

## Explicit controller-query compatibility evidence (receipt v2)

The query-policy checkpoint introduced `cs80-process-lifetime-child-v2`
and three explicit contract fields: `controller_query_policy` (1 strict SDK or
2 pinned JUCE false/null), `controller_query_result` (raw uint32 encoding of the
Linux SDK result), and `controller_query_pointer_present` (boolean). It binds all
three fields to the actual receipt and includes them in the frozen contract hash.
No result is relabeled as success or silently selected from a failed prior run.
A public v1 receipt cannot authorize this policy. Legacy v1 remains available only
to private inert fixture tests, under strict policy1.

On this Linux SDK, a combined controller requires result0 and a non-null pointer;
a separate controller requires result UINT32_MAX and null under strict policy.
Policy2 additionally permits exactly result1 and null. Controller class identity
must match that combined/separate outcome. Unknown policy values, success/null,
failure/non-null, missing expected policy and mismatched raw evidence fail closed.
This query policy is independent of the controller serialized-state policy.

The native driver/request retains the strict default. Selecting compatibility in
a new frozen request is an explicit new experiment, not a retry that converts an
old failed attempt into a pass. Authentic plugin execution remains separate from
these inert controls.

Before any public child launch, the parent reads the same owned, private, bounded
request and checks its SHA256. It independently decodes the versioned header and
requires exact agreement with the parent profile, arm, class CID, all five frozen
workload selectors, serialized-state policy and query policy. Request-v1 implies
strict policy1; request-v2 carries an explicit policy. A mismatched compatibility
request is rejected before native execution, not merely after seeing a receipt.
The native parser remains responsible for validating the complete identity/caps
tail. Header checks do not replace that parser or prove runtime closure.


## Explicit disabled-mono-input topology (receipt v3)

The public standalone path now requires receipt-v3 and explicit contract field
`audio_input_topology`: 1 for the unchanged zero-audio-input profile, or 2 for
one disabled mono external-input bus. Receipts-v1/v2 are private fixture-only and
cannot select topology2. Request-v3 carries topology after query policy;
request-v1/v2 imply topology1. The parent checks this before launching, and binds
the actual receipt topology and frozen contract hash to the expectation.

For topology2 the parent additionally requires the frozen render protocol header
`CS80RPRT`, version2, topology2, along with the exact externally expected protocol
hash. The canonical A-D lifecycle must contain exactly three successful
`external-input-disable` calls, one before each component activation and each
immediately followed by successful output-bus activation. Missing, duplicate,
failed or reordered disable calls fail admission. Topology1 requires no such
calls. Native descriptor/metadata checks remain the frozen producer's
responsibility; a receipt alone is not proof of arbitrary plugin behavior.

No input is enabled, no samples are routed from the external input, and no
production plugin/SDK change or CPU timing claim is authorized by this profile.
