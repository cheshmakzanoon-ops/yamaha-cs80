# Zero-audio control flush: preparation only

`flushObserved` accepts a session implementing the owned private-phase-checked `withProcessingOperation` wrapper, not a caller-supplied Processing enum. The wrapper must attest its initialized/setup/active/processing lifetime, catch failures, latch terminal and run checked cleanup. Current standalone tests use an inert fake session; actual initializer integration is a separate gate. Correct processing thread and host health before/after remain mandatory caller/session contracts.

The frozen protocol carries current realtime/offline mode and a complete, ordered nonempty control roster: one finite normalized point at offset0 for each unique ID, at most4096. IDs must exactly match the independently frozen expected roster; that roster's native metadata binding and completeness are outside this helper. This supports a distinct frozen roster per initial/alter phase, not arbitrary omitted controls.

ProcessData remains float32 with **zero samples, zero inputs, zero outputs**, null audio arrays/events/context, bounded input and output parameter interfaces. Offset0 on output parameters is a control boundary only. Internally the bounded queue accepts that single offset; this is never one audio frame, no PCM is allocated or encoded, no audio clock advances and no history-reset assertion is made. Existing render protocols still require positive audio frame counts.

Exact pinned SDK `ivstaudioprocessor.h` documents zero-channel flush and Processing/thread requirements. JUCE wrapper3683–3733 applies input parameters before explicitly skipping audio when all three audio dimensions are zero. The observer therefore must flush only after checked setProcessing(true), never copy the earlier fixture's preactivation flush uncritically. This source analysis is not a real-runtime pass.

The receipt retains attempted/returned/result/exception, descriptor/queue validity, canonical input bytes and all accepted output points even on ordinary process failure. Ignored invalid output attempts latch failure. Every descriptor mutation, input mutation, bad return/throw or rejection makes the session wrapper terminal. Output points are bounded4096, offset0 only and retain queue/point order. Local allocation failures, native crash/hang and hostile memory writes require external subprocess evidence; this helper is not a sandbox or resource-time limit.

Encoding is v1, little-endian, fieldwise, with domain-separated input/observation tags and length-delimited embedded canonical inputs. Audio dimensions explicitly remain zero. Input identity drift and unadmitted/malformed output receipts fail. This encoding proves structure/binding only, not that public receipt fields came from authentic execution. Empty output queues are not preserved as identities, only the point stream. Borrowed queue interfaces may not escape the synchronous call; this correctness adapter allocates and is not timing evidence.
