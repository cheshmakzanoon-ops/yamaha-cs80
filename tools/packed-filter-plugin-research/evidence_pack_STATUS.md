# Prospective content-addressed evidence pack (preparation only)

No CLI, upload, remote deletion, credential use or synth/plugin execution. Tests use tiny inert files only. Actual qualification archives have not been packed, timed or measured.

`pack` scans complete independently located per-arm roots, preserving every directory (including empty ones) and regular file's relative path, type, POSIX mode, size and SHA256. It rejects symlinks, hard links, special files, overlap, special permission bits and unreadable entries. Same-digest files are compared byte-for-byte before deduplication. Sources are rescanned before publication, ZIP content is fully verified, and exclusive publication never replaces an existing destination. A failure removes only its own unpublished temporary archive, not source evidence.

All calls require explicit positive integer caps for logical raw bytes (counting duplicates across arms), compressed archive bytes, manifest bytes and total filesystem entries. The supported envelope additionally limits compressed bytes to 2 GiB, manifest bytes to 64 MiB and entries to 60,000. ZIP comments, split archives and ZIP64 end-directory envelopes are unsupported. ZIP64 local file headers are permitted. The ZIP central-directory allocation is bounded before Python materializes entries. Caps are technical rejection limits, not a spending or launch authorization.

`verify_archive` rejects duplicate ZIP/JSON/path entries, missing/extra blobs, traversal, inconsistent sizes/modes/parents, unsupported ZIP entries and any byte/hash mismatch. Every retained blob must be referenced by the complete manifest. `restore` requires a fresh destination, rehashes actual reconstructed file bytes, restores modes, and independently rescans each full arm against the manifest. Archive bytes are rehashed again after restoration. Existing destinations are never overwritten. A restore failure may leave a partial fresh directory for audit and must make the surrounding experiment terminal.

Ownership, stopped writers and stable filesystem state are mandatory. This is not a race-proof sandbox or a general hostile-archive extractor. Only file contents, directory inventories and POSIX modes are represented; owners, ACLs, timestamps and extended attributes are not preserved. A full Stage A integration must determine whether those additional attributes matter. Packing reports that reconstruction is still required; only an actual verified `restore` clears that requirement. No method can declare production qualification.

The caller must freeze complete arm-root inventories independently of this helper, retain all command/result/failure evidence, verify actual artifact size against the approved envelope, and establish public-runner/storage billing and retention limits. The helper does not infer completeness from two identically incomplete input directories and does not prove which native processes produced the input files.
